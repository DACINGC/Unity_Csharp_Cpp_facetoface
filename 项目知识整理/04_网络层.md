# 四、网络层

> 本章讲项目网络层：HTTP/TCP/UDP(KCP) 四通道分工、验证服→代理服两级连接、MsgId 关联的 RPC 回调机制、KCP 可靠 UDP 原理、心跳与三级重连防线。KCP 与断线重连是网络面试高频。

## 4.1 四通道架构（为什么这么分 ★★★）

| 通道 | 承载内容 | 选型理由 |
| --- | --- | --- |
| HTTP | 服务器列表、旁路请求 | 简单可靠，不需要长连接 |
| TCP | 登录/RPC/逻辑主通道 | 可靠有序，命令式业务天然匹配 |
| UDP + **KCP** | 战斗移动/技能/伤害/Ping | 战斗高频消息要低延迟；原生 UDP 不可靠 → 叠 KCP 实现**可靠 UDP**（自带重传/有序/拥塞控制） |
| 内存队列 | 跨线程收发包 → 主线程统一处理 | socket 回调/KCP 线程都只投递并发队列（ActionQueue/KcpPkgPipe/PkgPipe），**Unity API 只在主线程碰** |

- 包格式：19 字节公共头 `PkgLen|PkgFlag|PkgCmd|Uin|RoleId|MsgId` + MemoryPack 序列化负载，大端序。
- **面试点**：为什么战斗用 UDP？——TCP 队头阻塞：一个包丢了后面的包全堵住；KCP 用"可靠 UDP"拿到"不丢包 + 不阻塞"（丢了只重传自己），适合实时对战。

## 4.2 连接生命周期：验证服 → 代理服（两级连接 ★★）

```
HTTP 拉服务器列表 → 随机选验证服 → TCP 连接验证服 → 认证请求
→ 认证响应下发【代理服】TCP/UDP 地址 → 断开验证服、连接代理服
→ 拉角色列表 → 登录 → 服务器全量推送角色数据
```

- **客户端从不直连游戏服**：代理服承载全部流量，游戏服对客户端透明——换服/扩容/负载均衡对客户端无感（经典网关架构）。
- 登录两段式：验证服只做认证（顺带换回可用的代理服地址），代理服做后续一切。

## 4.3 RPC 与消息分发

### 4.3.1 注册表：cmd → 处理函数

- `RpcServer.mMemoryPackProcessFunc`（Dictionary<ushort, 处理函数>）；启动时 `NetMsgCenter.Init` 依次初始化 **30 个 Net\*Msg 模块**（战斗/房间/英雄/背包/公会/交易/钓鱼…**按功能域一个模块**），每个模块 `Add(GameCmd.XXX, R_XXX)` 注册自己的协议。
- 处理函数模式：解码 MemoryPack → `GameEventCenter.SendEvent` 广播给业务层（网络层不碰 UI/逻辑，只做搬运+广播）。

### 4.3.2 请求-响应关联（MsgId + 超时 ★★）

```
CallServer<T>(cmd, msg, callback)
  → 自增 MsgId 写入包头 → 注册 MemoryPackCallInfo（回调 + 10s 超时时间戳）
  → 服务器回包带相同 MsgId → RpcClient.ProcessPkg 命中回调并移除
  → 超时未回 → Update 扫描到期 → ontime 回调
```

- **MsgId 关联**让同 cmd 并发多次请求不串回调；`CallServerImport`（重要消息）超时 2s **自动重发最多 5 次**，再失败判定掉线。

## 4.4 KCP：可靠 UDP（★★★ 高频）

### 4.4.1 为什么需要 KCP（对比 TCP）

- TCP：可靠+有序，但**丢包会阻塞后续所有包**（队头阻塞），拥塞控制保守，实时对战延迟抖动大。
- KCP：UDP 之上自己实现**选择性重传（只重传丢的包）+ 快速重传 + 滑窗 + 拥塞控制**，参数可调（`nodelay=2` 快速模式：10ms 间隔、5 次快重传、RTO 快速递增）——**牺牲 10%~20% 带宽换 30%~40% 延迟降低**（KCP 作者原话）。

### 4.4.2 项目中的落地

- 独立 **KcpThread 线程**死循环：从 KcpPkgPipe 取包 `KCPPcb.Input`（重组）→ `KCPPcb.Update`（驱动 flush/ACK/重传）→ `Recv` 取完整应用包 → 投 PkgPipe 主线程分发；发包 `KCPPcb.Send`（按 MSS 分包入发送队列）→ flush 时经 UDP Socket 发出。
- 参数：MTU 1400（mss 1374）、收发窗口 32/128、死链判定 20 次重传失败；战斗 Ping 每 5s 一发走 UDP 回显测延迟。

### 4.4.3 面试答题要点

"KCP 是纯算法库（无底层协议），把 UDP 包装成可靠连接：ARQ 自动重传、快速重传（收到 3+ 次重复 ACK 直接重发不等超时）、滑动窗口流量控制、拥塞控制（ssthresh/cwnd）；和 TCP 的区别在于可以牺牲带宽换延迟、参数可调、不阻塞。适合游戏/实时音视频。"

## 4.5 心跳与断线重连（★★★ 高频）

### 4.5.1 心跳（双通道 + 时钟同步）

- 进游戏后每 **1s**（单人战场 0.5s）TCP 与 UDP **各发一次**心跳（`REQ/RSP_GAME_ROLE_HEART_BEAT`）；回包顺带**时钟同步**（服务器时间戳校准客户端 `TimeHelper.DeltaTime`）——预测/校验/插值全靠这个对齐的时间基准。

### 4.5.2 掉线检测（三级防线）

```
① 超时检测：仅 TCP 包刷新存活时间（UDP 战斗包不算"存活证明"，必须 TCP 心跳续命）
    阈值：登录后 2s / 创角阶段 60s / 单人战场 1s
② 软重连：UpdateDisConnectedState 每 3s 重试 ConnectProxySvrd
    → REQ_GLOBAL_ROLE_RECONNECT{RoleKey, MachineCode} → 成功恢复界面（刷新引导）+ 清计数
③ 防重连风暴熔断：CheckRecountLimitOut（8 次/5s 超限）→ 放弃 → 弹掉线框回登录
```

- 其他触发点：切后台恢复（OnApplicationPause）、TCP 发送异常兜底；
- **断线恢复**：`ResendImportantMessage` 广播 `GUIDE_UPDATED` 让引导/界面重新自检；关键消息由 `CallServerImport` 自动重发兜底；
- 单人战场（本地模拟服务器）里断线无感——本地逻辑继续跑，重连只是恢复外网交互。

### 4.5.3 面试追问预案

- "为什么 TCP 有重传还要 KCP？" → §4.4.1 队头阻塞 + 延迟；
- "心跳为什么要双通道发？" → UDP 通但 TCP 断可能是 NAT/代理差异，双通道互为探测，UDP 心跳保 NAT 映射（打洞存活）；
- "断线重连怎么恢复战斗状态？" → 服务器保存战场快照（角色/位置/技能），`REQ_GLOBAL_ROLE_RECONNECT` 响应带恢复数据，客户端重建表现层；本项目单人战场本地模拟更简单——本地战斗世界还在，只恢复 UI 与引导。
