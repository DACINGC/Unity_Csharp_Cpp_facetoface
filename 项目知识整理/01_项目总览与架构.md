# 一、项目总览与架构

> 本章是**项目知识整理**的第一篇：项目基本情况、系统全景地图、总体架构决策。面试"介绍你的项目"时按 §1.3 的话术组织；各系统细节见 §2~§7，高频问答见 §8。

## 1.1 项目基本情况

### 1.1.1 项目类型与技术栈

- **类型**：Unity 客户端 **2D 横版动作/格斗类手游**（英雄养成 + PVE 副本 + PVP 竞技 + 组队玩法），服务器为 C# .NET 8 微服务，**双端共享战斗核心代码**（§1.2.2）。
- **客户端技术栈**：
  - 引擎与语言：Unity + C#（UGUI、Mono/IL2CPP 双后端）；
  - 网络：TCP（登录/逻辑）+ **UDP 叠加 KCP 可靠传输**（战斗）+ HTTP（旁路），MemoryPack 序列化（§4.1）；
  - 配置：**Luban 二进制配置表** + YAML 杂表 + 技能编辑器导出 JSON（§6.1）；
  - 资源：自研 AssetBundle 体系 + **CDN 热更新**（Hash 差异下载）（§5.2）；
  - 动画/UI：Spine + DOTween + TextMeshPro；AI：behaviac 行为树；异步：UniTask；DI：Autofac（服务器侧）；
  - 热更：**资源热更 + 配置热更，无 C# 代码热更**（§5.5）。

### 1.1.2 系统全景地图（一句话概括每个系统）

| 系统 | 一句话概括 |
| --- | --- |
| 战斗系统 §2 | 一套纯逻辑战斗核心**同时编译进服务器与客户端**，客户端预测+服务器权威，连招树+指令缓存保证格斗手感 |
| UI 框架 §3 | **层 = Canvas、层号 = sortingOrder** 的分层导航栈 + ViewController 式页面 + 强类型事件总线 |
| 网络层 §4 | HTTP/TCP/UDP+KCP 四通道；**验证服认证→代理服承载**两级连接；MsgId 关联的 RPC 回调 |
| 游戏状态机 §8.2 | 注册表式状态机（Enter/Exit 动作对）+ **正交错误状态**（断线不干扰主流程）+ 主城战斗同场景 |
| 配置系统 §6 | **Luban 三层架构**（生成代码 / partial 手写扩展 / 语义化接口），外键 `_Ref` 自动引用解析 |
| 新手引导 §7 | 配置表驱动 + `GUIDE_UPDATED` **事件循环**（各监听者自行判定是否轮到自己的步骤） |
| 数据与存档 §6.4 | **服务器权威**：登录全量推送 + 运行期增量合并，客户端零核心存档（sqlite 已废弃） |
| 热更新 §5 | CDN 清单 + 资源级 Hash 差异下载 + **双目录加载覆盖**（streaming 内置 / persist 热更） |

## 1.2 总体架构设计

### 1.2.1 三层架构（表现/逻辑/数据）

```
表现层（客户端专属）   UI 框架(§3) + 场景/动画/特效/相机 + 战斗表现层
逻辑层（双端共享）     战斗核心(§2) + 玩法模块 Manager（ModelManager 模块注册表）
数据层（双端共享）     配置系统(§6 Luban 表) + 网络协议(MemoryPack) + 服务器数据推送
```

- 规则：上层依赖下层、禁止反向依赖；逻辑层**不引用 UnityEngine**，可独立编译（§1.2.2）。
- 模块间通信：**强类型事件总线** `GameEventCenter`（`Event<T1..T6>` 静态字段声明，编译期类型安全）+ 网络消息注册表。

### 1.2.2 双端共享核心（项目最重要的架构决策 ★★★）

- **动机**：单机副本要"零延迟丝滑手感"，联机对战要"服务器权威防作弊"，若写两套逻辑必然漂移。
- **做法**：把战斗逻辑（`Script/thirdlib/Battle/`）抽成**纯 C# 逻辑库，不依赖 UnityEngine**：
  - **服务器**：通过 `ThirdLib.csproj`（net8.0 + `SJ_SERVER` 宏）编译成 DLL 给游戏服务器用——服务器就是权威裁判；
  - **客户端**：同一份 .cs 源码被 Unity 直接编译进包——跑本地逻辑；
  - **单人副本**：客户端把逻辑核心跑在自己进程里，用**本地 RPC 回环**冒充服务器（`SingleBattleWorld`，`IsClientWorld=true`），输入请求走与联机完全相同的协议路径 → **单机=联机行为天然一致**。
- **面试说法**："一套逻辑两种身份（裁判员/运动员），单机联机零漂移"；顺带可引出热更里"逻辑层无引擎依赖所以可独立测试/可复用"的工程收益。

### 1.2.3 模块化管理器体系

- **ModelManager**（模型注册表）：`GameModelType` 枚举下标索引数组，注册 Scene/Http/Battle/Input/SingleBattle/Replay 六大模型；`BaseModuleModel` 提供 Init/Clear/BeforeUpdate/Update/AfterUpdate 生命周期；战斗期才把 SceneManager 挂进更新列表（`InitSceneInfo`），退出摘除（`ClearSceneInfo`）——**不用的模块不被驱动**。
- **ControllerManager**（控制器注册表）：InputSystem（输入）/GlobalController（心跳重连）/SceneController（战斗事件转发）/CameraController（动态添加）。
- 单例体系：`MonoSingleton<T>`（CRTP，懒加载自动建 GameObject 挂 DontDestroyOnLoad 的 SingletonRoot、防重复）+ 纯 C# `Singleton<T>` + 静态类（GameCfgMgr）。

### 1.2.4 全局驱动链（Unity 主循环如何分配）

```
Unity Update → GameControllerUpdater（MonoSingleton，唯一全局驱动器）
  → ControllerManager.BeforeUpdate/Update → ModelManager.Update
  → TimerDispatcher.Update（线程→主线程回调队列，单帧上限 100 个）
Unity LateUpdate → ModelManager.AfterUpdate + ResourcePool.Update + CameraController.AfterUpdate
战斗期：SceneManager.Update → TickComponent（逻辑时钟，与渲染帧解耦）→ 战场 Tick → Actor 组件
网络：NetworkMgr.Update 由 GlobalController.BeforeUpdate 驱动；KCP 跑独立线程（§4.4）
```

- **面试点**：逻辑层用**自洽时钟**（服务器 50ms 固定心跳 / 客户端挂 Update 但按时间戳对齐），物理与表现分离，预测/回滚才可能对齐。

## 1.3 面试"介绍项目"话术（30 秒版 + 2 分钟版）

### 1.3.1 30 秒版（一句话项目）

"这是一个 Unity 的 2D 横版动作手游，我做客户端。项目最大的特点是一套纯 C# 战斗核心同时跑在服务器和客户端——服务器当权威裁判、客户端本地预测保证手感，单人副本用本地回环模拟服务器，所以单机联机行为完全一致；UI 是自研的分层导航框架，网络是 TCP+UDP(KCP) 双通道，资源走 CDN Hash 差异热更。"

### 1.3.2 2 分钟版（分模块展开）

1. **战斗**（§2）：组件化角色（移动/技能/受击/状态/Buff 13 个组件）；移动做客户端预测 + 服务器校验回拉 + 远端插值；技能是配置驱动的连招树 + 本地先行/服务器裁决；指令缓存保证"按键不被吞"。
2. **UI**（§3）：层=Canvas、层号=排序；三种层控制器（覆盖/栈/常驻）；页面 = ViewController + 生命周期钩子；事件总线解耦——为什么不用 MVC（§3.4）。
3. **网络**（§4）：验证服→代理服两级连接；MsgId 关联 RPC 回调；KCP 可靠 UDP 扛战斗消息；心跳双通道 + 三级重连防线。
4. **工程化**（§5/§6/§7）：CDN 热更（清单+Hash 差异+双目录）；Luban 三层配置（生成/扩展/接口）；引导系统配置驱动+事件循环；数据全服务器权威。

> 面试技巧：每讲一个模块收尾时抛一个"为什么这么设计"的钩子（如"为什么 UI 不用 MVC"、"为什么战斗逻辑放服务器也编译一份"），引导面试官问你已经准备好的问题。
