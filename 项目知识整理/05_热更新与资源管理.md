# 五、热更新与资源管理

> 本章讲项目热更新：AssetBundle + CDN 版本清单 + Hash 差异下载 + 双目录加载覆盖；配置表热重载；以及面试高频的"C# 代码热更方案选型"（HybridCLR vs ILRuntime vs Mono JIT vs Lua）。

## 5.1 热更能力总览（先讲结论 ★★★）

| 内容 | 是否可热更 | 方式 |
| --- | --- | --- |
| 资源（UI Prefab/模型/贴图/特效/音频） | ✅ | AssetBundle（.dat）→ CDN 下载到可写目录 |
| 配置表（Luban 二进制表/技能 JSON） | ✅ | 同一套清单管线下载，覆盖加载 |
| C# 代码 | ❌ | 无 ILRuntime/HybridCLR，逻辑修复靠整包更新（SDK 商店升级） |

- 一句话架构："**CDN 拉版本清单 → 校验 baseVersion（基础包一致性）与 fixVersion（热更版本号）→ 按资源 Hash 差异逐文件下载 → 运行时双清单合并 + 双目录加载，Hash 不同的资源自动用热更版**"。

## 5.2 核心机制：双目录 + Hash 覆盖

### 5.2.1 资源双目录

```
内置目录（随安装包）:  StreamingAssets/gameres/*.dat       ← 基础版本资源（只读）
热更目录（可写）:      PersistentDataPath/gameres/*.dat    ← 下载的新版资源
                      （PC 特例：安装目录/presistentAssets，卸载时连带删除）
```

- 加载时按清单里的 `mIsBaseAsset` 标记选目录：`false → AssetBundle.LoadFromFile(persist路径)` ——**同一个资源 key，热更目录有新版就自动用新版**。

### 5.2.2 双清单合并（资源级粒度）

- **基础清单**：打包时生成、打进 Resources 的 `resConfig`（JSON：baseVersion / fixVersion / info{资源名→BundleName+Hash+依赖} / configs{配置→Hash}）；
- **热更清单**：热更下载到 `persistentDataPath/resConfig.txt` 的增量清单；
- 启动时 `UpdateResConfigData` **按 Hash 逐条对比合并**：Hash 不同 → 替换条目并标记 `mIsBaseAsset=false`（指向热更目录）；本地没有的新资源 → 直接加入；`fixVersion` 同步。

### 5.2.3 为什么是"资源级差异"而不是整包

- 清单里每个资源单独记 Hash，**只下载 Hash 变化的 AB**——改一张图只下一个 AB，不下载整个包；AB 文件名带 Hash（`bundleName_hash.dat`）天然可共存多版本。

## 5.3 启动更新流程（CheckFix 七步 ★★）

```
① 拼 URL：NetworkMgr.FIX_ADDRESS(=NGINX CDN + "/clientfix") + "/resConfig.txt"
② UnityWebRequest.Get 下载远程清单（BypassCertificateHandler 绕过证书校验）
③ 解析远程 ResourceConfig（JSON）
④ 版本校验两道闸：
    baseVersion 不一致 → "基础版本不一致" → 卡死（必须整包更新）
    remote.fixVersion <= local.fixVersion → "无需热更" → 直接跳过
⑤ 保存清单到 persistentDataPath/resConfig.txt
⑥ CompareAndCollectUpdates：逐资源/配置按 Hash 对比，收集下载列表
⑦ DownloadUpdatedAssets：逐文件下载（失败重试 5 次，仍失败卡死提示"检查网络后重启游戏"）
   资源 → persist/gameres/；配置 → persist/gameres/config/
→ ReloadPreResources：重读双清单合并 + 重新预加载
```

- 下载进度经 LoadingManager 显示在启动 Loading 界面（加载管线分步监听）。
- **强校验失败即卡死**策略（不静默降级）：避免"清单失败却用旧资源进游戏"导致玩家数据不一致。

## 5.4 配置表热更（Luban）

- 配置与资源走**同一套清单与下载管线**（configs 段），下载到 `persist/gameres/config/`；
- 客户端：`ReloadHotFixCfg(loader)` 支持按自定义 loader 重建表；首启动从 StreamingAssets 拷贝、热更覆盖；
- 服务器：`FileSystemWatcher` 监视表文件变化 → 自动重载**运营类 4 张表**（激活码/礼包码/系统邮件/奖励）——服务器无需重启即可更新运营配置（`#if SJ_SERVER`）。

## 5.5 C# 代码热更方案选型（★★★ 面试必问）

### 5.5.1 项目现状与历史

- 当前**无代码热更**；代码里有已注释的 `InitLuaEnv`（`LuaManager.PatchHotfix`）——早期 xLua/ToLua 方案的遗迹，已废弃。
- 注意区分：`ThirdLib.csproj`（net8.0 + `SJ_SERVER` 宏）编译出的 DLL 是给**服务器**用的共享逻辑库，不是客户端热更。

### 5.5.2 市面主流方案对比（面试必背表格）

| 方案 | 原理 | 语言 | iOS | 性能 | 改造成本 | 现状 |
| --- | --- | --- | --- | --- | --- | --- |
| **HybridCLR**（原 huatuo） | IL2CPP 环境下补充 C++ 实现的 **IL 解释器 + 运行时补元数据**，热更 DLL 解释执行且能继承 AOT 类/实现接口 | C# | ✅ | 解释执行（良） | 低（拆程序集） | **当前主流，新项目首选**，Unity 中国官方认可 |
| **ILRuntime** | **纯 C# 实现的 IL 解释器**（虚拟机），热更 DLL 由它解释执行，跨域交互需 CLR 绑定/重定向 | C# | ✅ | 解释执行（一般） | 中（写适配器） | 存量最大（腾讯开源），维护放缓 |
| Mono JIT + `Assembly.Load(byte[])` | Mono 后端 JIT 支持运行时加载 DLL 直接执行 | C# | ❌ | JIT（好） | 低 | 淘汰边缘（iOS 禁止 JIT，Android 也转 IL2CPP） |
| xLua / ToLua | 逻辑写 Lua，C# 做引擎层，Lua 脚本热更 | Lua | ✅ | 解释执行 | 中高（双语言协作） | 被 C# 直热更挤压，老项目在用 |
| Roslyn 运行时编译 | 运行时把 C# 源码编译成 IL 再加载 | C# | ❌ | JIT | — | 基本无商业游戏用 |
| InjectFix | IL2CPP 静态注入 + 小型 IL 解释器，定位修 bug | C# | ✅ | — | — | 已停更 |

### 5.5.3 若本项目要接入的推荐方案（面试话术）

"选 **HybridCLR**：热更代码用原生 C#、与 AOT 代码零边界（继承/接口/泛型）、iOS 可用、改造成本最低；架构上把客户端业务逻辑拆成 AOT 主工程（框架稳定）+ 热更程序集（UI/玩法/活动）；热更 DLL 当普通资源进现有 CDN + Hash 差异管线，下载到 persist 后 `Assembly.Load` 加载——**资源热更与代码热更统一成一条管线**。风险提示：iOS 审核对'下载解释执行代码'是灰色地带，国内渠道通行、出海需评估（Unity 官方口径只背书资源热更）——折中是出海包只热更资源/配置。"

## 5.6 面试常见追问

<details>
<summary>Q：热更下载一半断网/杀进程怎么办？</summary>

清单是"先下载后生效"：全部文件下载成功才写回最终 resConfig.txt（SaveResourceConfig 在最后），下次启动按新清单走；失败的文件不会进入清单，旧资源继续可用——天然原子性（写清单文件是提交点）。补充：单个文件下载失败重试 5 次仍失败则卡死让玩家重启，不静默带病运行。</details>

<details>
<summary>Q：AB 依赖怎么处理热更？</summary>

清单里每个资源记录依赖（依赖 AB 名+Hash）；UpdateResConfigData 合并时依赖引用整体切换；加载时按资源入口的 mIsBaseAsset 决定读哪个目录，依赖链随主资源走同一目录——同一版本资源之间引用，不跨版本混用。</details>

<details>
<summary>Q：为什么不用 Addressables？</summary>

项目是自研 AB 体系（打包工具/清单/Hash/热更管线一体），Addressables 的优势（编辑器工作流/远程目录/版本化）与自研体系重叠；自研清单支持资源级 Hash 差异、fixVersion 双版本校验等定制需求。面试时也可说：自研方案在"热更粒度、版本校验、断点重试"上更贴合项目，成本是一次性投入。</details>
