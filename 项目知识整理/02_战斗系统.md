# 二、战斗系统

> 本章是项目面试的**核心卖点章节**（★★★ 必讲）：双端共用战斗核心、移动预测回滚、连招树、本地先行施法、打击感。讲的时候按"架构 → 移动同步 → 技能连招 → 输入手感"递进，每个知识点给一句话设计动机 + 一句面试话术。

## 2.1 战斗架构总览

### 2.1.1 一套逻辑、两种身份（客户端/服务器共用核心 ★★★）

- 战斗逻辑（位置/血量/技能状态/伤害结算）是**纯 C# 库、无 UnityEngine 依赖**（`thirdlib/Battle` + `thirdlib/Mgr`），同时编译进服务器与客户端（详见 §1.2.2）。
- 三级容器：**世界 BattleWorld（一组关卡）→ 战场 BattleField（一场战斗：地图边界/胜负/状态机）→ 角色 Actor → 组件 Component**，服务器 50ms 固定心跳逐层 Tick，逻辑时钟自洽、不依赖渲染帧率。
- 客户端表现层（`SceneManager`/`Player`）通过 **ActorProxyObject 桥接**逻辑层——表现层只读逻辑数据、只做动画特效，改动一律走输入指令。

### 2.1.2 组件化角色（组合优于继承）

- 角色 = 组件容器（构造后 `OnInit` 一次装配 13 个组件）：移动 Move / 技能 Skill / 受击 Hit / 状态 State / 属性 Attr / 表现 Perform / 保护 Protect / Buff / 记录 / 召唤 / 牵引 Pull / 时间膨胀（时停）/ 逃脱技 DriveGuard。
- **状态是"标记字典 + 检查点显式询问"，没有互斥表**：每个动作执行前问自己"能移动吗 = 没死？没受击？没有禁移动状态？技能允许打断？"——新状态只加一行判断，不用维护 N×N 互斥表（对比 FSM 的优劣见 §9.3）。

### 2.1.3 战场状态机与驱动

- 战场状态：Init → WaitStart → Battling → Count → WaitEnd → End（每帧 `OnTick → ActorUpdate` 遍历角色 `UpdateUs`）；角色按类型有不同 Update（玩家走预测时间戳/服务器托管，怪物/NPC 走 behaviac AI）。

## 2.2 移动与同步（面试最高频 ★★★）

### 2.2.1 移动框架

- 移动组件双端共用同一套物理：`ClientUpdate → CheckJumpInput/CheckMoveInput → PerformMovement → PhysWalking/PhysFalling`（速度公式、重力、碰撞探测都在逻辑层，不依赖引擎物理）。
- 移动模式枚举：Walking/Falling/Swimming/Flying…；**跳跃 = 移动模式切换（地面↔空中）**，所以跳跃标志（`FLAG_JumpPressed`）直接混在移动包里传输，**没有独立跳跃协议**。

### 2.2.2 客户端预测 + 服务器校验 + 回滚（★ 必背）

```
客户端预测：本地立即执行输入并逐帧模拟 → SaveMove 帧缓存（时间戳/位置/速度/跳跃标志）
  → 50ms 合并打包 REQ_GAME_NEW_ACTOR_MOVE（UDP/KCP）
服务器校验：用同一套物理重放客户端输入（ServerPerformMovement）
  → 通过（时间戳合法 + 位置误差 < 阈值）→ 回 RSP 确认（ClientAckGoodMove）
  → 失败 → 回 RSP 带"权威快照" → 客户端 ClientAdjustPosition 整体回拉（位置/速度/旋转/移动模式/受击状态）
远端表现：服务器广播 NTF_GAME_NEW_ACTOR_MOVE → 其他客户端 SimulatedTick + SmoothClientPosition
  （UE5 风格 NewSmoothCorrect：按时间戳插值"追"目标，不瞬移）
```

- **三个关键词**：预测（手感）→ 校验（公平）→ 插值（观感）；时间戳是三者对齐的锚点。
- 服务器对客户端是"**校验+采信**"混合：不重算物理从头模拟，而是重放客户端输入、超阈值才回拉（省服务器算力，作弊也能被抓）。

### 2.2.3 跳跃的实现细节

- 触发链：UI 跳跃键/摇杆向上 → `InputCommandBuffer.InputJump` → `CanJump()`（未受击/未禁移动/次数未满）→ `DoJump()`：`Velocity.Z = √(JumpHeight × -2 × -4905)`（重力常量来自属性表 `JumpHeight/GPercentValue`）→ 进入 MoveFalling。
- **二段跳**：`JumpCurrentCount < GetMaxJumpCount()`；落地 `ProcessLanded → OnMoveModeChanged` 重置次数、**打断"跳不可控"技能**、死亡时判定复活。
- 面试点：跳跃是"移动标志"不是独立协议——一个输入一条链路，协议面最小化。

### 2.2.4 移动与技能的交互规则（手感来源）

- 施法中能否移动：配置 `SkillCfg.CanMove`；超过 `MoveBreakTime()`（收招可打断点）后才能移动打断；
- **根运动**：技能位移（SkillMotion）优先于摇杆移动，剩余时间随移动包同步，远端追帧；
- 受击（IsBeHit）/BanMove/BanCtrl 禁移；空中默认禁放技能（`ErrSkillCantCastInAir`）。

## 2.3 技能与连招

### 2.3.1 连招树（普攻连招核心 ★★★）

- 每个英雄的普攻/空攻/技能/大招组织成**一棵树**：根=起手技，子节点=后续段；节点字段：触发键 KeyCode、技能配置、`ComboCacheTime`（连招缓冲窗口）、`IsAutoCast`（自动连招）。
- 连续按键：在当前节点的 Children 里找按键匹配且条件通过的下一段；每段有**窗口期**（上一段收招开始 → 结束+缓冲时间），窗口内按下续段、超时"掉招"回根。
- **树由服务器构建并下发**（`ACTOR_ENTER_BATTLE.ComboNodeList`），客户端不建树只消费——连招合法性最终由服务器判定。
- 变体：窗口连招（只有首段有 CD，末段关窗给首段记 CD）、蓄力连招（按下开始/松开释放，`REQ_GAME_ACTOR_STORAGE`）、自动连招（`IsAutoCast` 收招自动续段）。

### 2.3.2 技能 = 配置驱动的动画时间轴

- 每个技能是**技能编辑器导出的配置**：阶段时长（抬手 Shake/释放 Cast/收招 Recruit）、子弹发射时间点、无敌帧、可控转向片段、打断等级、霸体等级、消耗、CD——代码只是"按时间轴推进的引擎"，**新技能 = 新配置零代码**。
- 运行时状态机：`SkillAction.Update`：Shake →（到点创建全部子弹）→ Attack → Recruit → End；每帧附带位移冲量/吸附/时间缩放/完美格挡。

### 2.3.3 本地先行 + 服务器裁决（施法同步 ★★★）

```
按键 → 连招树取节点 → Player.NewLocalCastSkill：本地立即起手（播动画、跑技能逻辑，零延迟手感）
  → 同时发 REQ_GAME_BATTLE_CAST_SKILL_COMBO（节点ID/方向/目标/移动信息）
服务器：SvrCheckSkillComboNodeCond 重新校验（CD/消耗/状态/连招窗口）→ 扣消耗、起手、广播 NTF
回包：成功 → 修正位置/流水号；失败 → 客户端 BreakSkillCast 打断 + 回滚 CD
```

- **账本只在服务器**：CD/蓝耗/伤害/掉落只服务器记账（客户端 UpdateSkillCd 直接 return），通过 `NTF_GAME_BATTLE_CD_LIST` 同步回客户端；客户端全量模拟子弹/命中只为表现。
- 一句话：**客户端负责"感觉"，服务器负责"事实"，流水号负责对齐**。

### 2.3.4 子弹与伤害链路

- 技能按时间轴在指定时间点 `CreateBullet` → 子弹状态机 Appear→Prepare→Flying→WaitEnd→End；飞行按类型分派（直线/追踪/曲线）；命中判定 **AABB 粗测 + GJK 精测**；可生成子子弹、支持替换与牵引。
- 伤害公式（PVE/PVP 两套，`DamageModule`）：防御减伤 → 等级压制 → 伤害加成/减免（保底 5%）→ 易伤 → 暴击判定 → 取整；命中时闪避判定只服务器执行。
- 受击（`HitComponent.StartHit`）：霸体对比（技能霸体等级 vs 攻击等级，Buff 蓝霸体第二层判定）→ 打断受击者技能 → 受击状态机（冻结/击退/击飞/击倒/扫地/起身，每态一套位移曲线）。

### 2.3.5 打击感体系（面试加分项）

- **命中时停**：HitTimeDilation 命中瞬间局部慢放（时停系数由命中配置驱动）；
- **霸体/保护**：SuperArmor（等级制）、黄保/红保/扫地保护防无限连；
- **交互打断**：受击打断技能、跳跃打断收招、落地打断不可控技能、格挡攒满触发反击；
- 伤害飘字/震屏/音效由事件驱动（`TAKE_DAMAGE` 等），表现层订阅。

## 2.4 输入与手感

### 2.4.1 输入管线（UI 与战斗解耦）

```
UI 按钮/摇杆 → GameEventCenter 事件 → InputSystem（键位映射：U=普攻/I/O=技能/J=天赋/L=星魂/N=大招）
  → InputCommandBuffer 指令缓存 → 战斗组件执行 + 发服务器
```

- 键位三层映射：物理按键 → 抽象动作（InputActionType）→ 连招树节点（KeyId）；大招与普攻**同一套链路**，只是绑定的连招树不同。

### 2.4.2 指令缓存（"按键不被吞" ★★★）

- 格斗游戏最破坏手感的是"硬直中按的键没反应"。做法：**条件不满足的输入先入缓存队列，角色状态一变（受击结束/落地/收招完成）自动补发执行，超时淘汰**；跳跃优先级最高（清空其他缓存）。
- 这是命令模式 + 观察者的组合应用：命令对象入队延迟执行，状态变化事件驱动出列重试。

### 2.4.3 战斗 UI 的输入细节

- 摇杆：26° 角度限制（强制十字方向）+ 0.25 死区 + 输出"键码+轴向值"；攻击按钮长按连发（>200ms 自动连招）；跳跃按钮上滑到攻击键联动攻击；蓄力按钮按住蓄力、松开释放。
