# 八、项目面试问答（高频题 + 答题要点）

> 本章把项目面试最高频的问题整理成 Q&A（答案要点 + 对应小节引用），每道题按"结论 → 关键点 → 引导追问"组织。展开细节跳转 §2~§7。

## 8.1 项目介绍类

<details>
<summary>Q1：介绍一下你的项目？</summary>

结论：Unity 2D 横版动作手游，我负责客户端（战斗/UI/网络/热更/引导都有参与）。按 §1.3.2 两分钟版：战斗双端共用核心（单机联机一致）→ UI 自研分层框架 → TCP+UDP(KCP) 网络 → CDN 热更 → Luban 配置 → 引导事件循环。每块收尾抛一个"为什么这么设计"的钩子。</details>

<details>
<summary>Q2：你在项目里负责什么？最有成就感/最有挑战的部分？</summary>

推荐答**战斗系统**（§2）：双端共用核心的架构决策（§2.1.1）、移动预测回滚（§2.2.2）、连招树+指令缓存（§2.3.1/§2.4.2）。挑战点话术："最大的挑战是让单机副本和联机对战用同一套战斗逻辑还都好玩——单机要零延迟、联机要防作弊，最终用'一套逻辑两种身份'解决，移动做客户端预测+服务器校验回拉，技能做本地先行+服务器裁决。"</details>

<details>
<summary>Q3：项目架构分几层？怎么解耦的？</summary>

三层（§1.2.1）：表现/逻辑/数据；解耦三板斧：① 逻辑层无引擎依赖（双端共享的前提）② 强类型事件总线（模块间零引用）③ 数据服务器权威（客户端只管表现）。可对照 §9.2 通用架构笔记。</details>

## 8.2 战斗系统类（技术深水区）

<details>
<summary>Q4：移动同步怎么做？（必问）</summary>

客户端预测 + 服务器校验 + 回滚 + 远端插值，四段话术见 §2.2.2。追问预案：为什么预测（手感）/为什么回滚（作弊与漂移）/误差阈值怎么定（经验值+可配置）/时间戳怎么对齐（心跳时钟同步 §4.5.1）。</details>

<details>
<summary>Q5：技能/攻击是怎么同步的？和移动有什么区别？</summary>

移动是**逐帧预测**（连续状态流）；技能是**本地先行+服务器裁决**（离散事件）：按键瞬间本地起手保证手感，发协议给服务器重新校验（CD/消耗/连招窗口），失败打断+回滚 CD（§2.3.3）。区别话术："移动错了慢慢拉回来就行，技能错了要立刻打断——所以技能用'先斩后奏+失败回滚'，移动用'边跑边校验'。"</details>

<details>
<summary>Q6：普攻连招怎么实现的？</summary>

连招树（§2.3.1）：树节点=技能段，按键在当前节点子节点里匹配下一段；窗口期判定（上一段收招开始→结束+缓冲）；树由服务器构建下发；变体：窗口连招（首段才有 CD）、蓄力连招、自动连招。画图讲：根→子→孙的树 + 时间轴。</details>

<details>
<summary>Q7：打击感怎么做出来的？</summary>

四件套（§2.3.5）：命中时停（HitTimeDilation 局部慢放）、霸体/保护体系（受击状态机+扫地保护防无限连）、交互打断（跳跃打断收招/受击打断技能）、表现层事件驱动（飘字/震屏/音效）。可补充：技能编辑器时间轴配置（无敌帧/位移冲量/吸附）让策划直接调手感。</details>

<details>
<summary>Q8：怎么防止外挂/作弊？</summary>

服务器权威四板斧（§2.3.3/§6.2）：① CD/蓝耗/伤害只服务器记账 ② 客户端技能请求服务器重新校验（SvrCheckSkillCond）③ 移动服务器重放校验+位置误差阈值 ④ 玩家数据零本地存档。结论：客户端只是"输入设备+渲染器"，一切值钱的都在服务器。</details>

<details>
<summary>Q9：战斗性能怎么优化？</summary>

① 逻辑与渲染分离：逻辑层自洽时钟（50ms 心跳），渲染帧率抖动不影响判定 ② 对象池（子弹/飘字/血条/定时器）③ 虚拟列表（战斗 UI 血条池化 33 个）④ 组件化懒更新（不用的模型不挂更新列表 §1.2.3）⑤ AB 分帧加载（maxItemsPerFrame）。可对照 §6.10 通用优化笔记。</details>

## 8.3 UI 与框架类

<details>
<summary>Q10：UI 框架怎么设计的？为什么不用 MVC/MVVM？（必问）</summary>

见 §3.4：层=Canvas+层号=排序；三种层控制器；ViewController 页面流+导航栈+事件总线；面试话术全文在 §3.4.2。</details>

<details>
<summary>Q11：UI 之间怎么通信/刷新？</summary>

强类型事件总线 GameEventCenter（Event<T1..T6> 编译期类型安全）：数据变化广播（血条/怒气/编队变化），UI 订阅刷新；层开关广播 LAYER_OPEN_EVENT（主城收起按钮面板）/GUIDE_UPDATED（引导刷新）。补充：context 传参（打开时投递数据 DTO）与工厂回调注入（按钮行为定制）两条同步通道。</details>

<details>
<summary>Q12：返回上一页/回到主页怎么实现？</summary>

导航栈+懒重建+路由重置（§3.2.1）：栈存名字不存引用，取栈顶时无实例就按名重建；跳转前 ResetCurLayerRoute(["home_layer"]) 把栈底换成目的地，关闭新页自动弹回主城；被踢/断线清路由防回退到脏页面。</details>

## 8.4 网络类

<details>
<summary>Q13：为什么战斗用 UDP？怎么解决 UDP 不可靠？（必问）</summary>

见 §4.4：TCP 队头阻塞 → 战斗高频消息用 UDP → 叠 KCP 拿可靠（ARQ/快速重传/滑窗/拥塞控制，牺牲带宽换延迟）；KCP 跑独立线程，主线程只碰队列。</details>

<details>
<summary>Q14：断线重连怎么做？</summary>

三级防线（§4.5.2）：超时检测（仅 TCP 刷新存活）→ 3s 周期软重连（REQ_GLOBAL_ROLE_RECONNECT）→ 8 次/5s 熔断放弃；心跳双通道+时钟同步；恢复后广播事件让界面自检（§7.4）。</details>

<details>
<summary>Q15：RPC 回调怎么设计？</summary>

MsgId 关联（§4.3.2）：包头带自增 MsgId，注册回调字典，回包按 MsgId 命中；10s 超时；重要消息 CallServerImport 2s 自动重发 5 次。优点：同 cmd 并发不串包。</details>

## 8.5 工程化类

<details>
<summary>Q16：热更新怎么做的？（必问）</summary>

见 §5.1~§5.4：CDN 清单+Hash 差异+双目录；无代码热更（如实说+方案对比 §5.5）。追问"如果做代码热更"→ HybridCLR 推荐方案 §5.5.3。</details>

<details>
<summary>Q17：配置表怎么用的？（数据驱动必问）</summary>

Luban 三层（§6.1.1）：生成/partial 扩展/语义接口；外键 _Ref；加工器校验链；运营表服务器热重载。话术："改数值改表、改逻辑改码；表必须配校验管线。"</details>

<details>
<summary>Q18：玩家数据怎么存？（防作弊必问）</summary>

服务器权威+零本地存档（§6.2）：登录全量推送+运行期增量合并（NtfType/DelHero）；写操作 REQ→RSP；本地只存登录态/设置缓存。</details>

<details>
<summary>Q19：新手引导怎么做的？（抽象能力考察）</summary>

配置驱动+事件循环（§7.1）：GUIDE_UPDATED 广播→监听器各自判定；UI 自动绑定零改动；强引导复制按钮接管点击；组粒度存档。亮点话术在 §7.1.2/§7.6。</details>

## 8.6 通用追问与踩坑

<details>
<summary>Q20：项目里踩过什么坑？怎么解决的？</summary>

选 2~3 个真实的：① 引导步骤进度不落盘导致断线重连重复引导（§7.4 取舍）② 确认框 ResetButtonInfo 参数误传导致按钮显隐异常（UI 框架细节 bug）③ GBK/UTF-8 编码混杂导致中文注释乱码、文件读取报错（工程规范问题）④ 弹窗与引导互斥（事件联动解决 §7.2.3）。每个坑讲"现象→定位→修复→教训"。</details>

<details>
<summary>Q21：和队友协作怎么分工/保证质量？</summary>

配置驱动让策划自治（改表不发版）；代码规范：region 分区、对称注册约定（UI 事件注册/反注册）；双端共用代码约束（逻辑层不许引用 UnityEngine——架构即规范）；校验链（配置 CfgCheck、协议注册表日志"Not Regist"兜底）。</details>

<details>
<summary>Q22：如果重做这个项目，你会改什么？</summary>

① 补 C# 代码热更（HybridCLR，§5.5）② 引导步骤进度落盘（§7.4）③ UI 层考虑引入 MVVM 绑定（复杂度可控的页面）④ 网络层协议生成工具化（MemoryPack 消息手写字段易错）⑤ 统一编码规范（GBK 历史遗留）。显示反思能力。</details>
