# 八、项目面试问答（高频题 + 答题要点）

> 本章把项目面试最高频的问题整理成 Q&A（答案要点 + 对应小节引用），每道题按"结论 → 关键点 → 引导追问"组织。每题都是独立小节，可在左侧目录直接点击跳转定位；细节可跳转 §2~§7。

## 8.1 项目介绍类

### 8.1.1 Q1：介绍一下你的项目？

结论：Unity 2D 横版动作手游，我负责客户端（战斗/UI/网络/热更/引导都有参与）。按 §1.3.2 两分钟版：战斗双端共用核心（单机联机一致）→ UI 自研分层框架 → TCP+UDP(KCP) 网络 → CDN 热更 → Luban 配置 → 引导事件循环。每块收尾抛一个"为什么这么设计"的钩子。

### 8.1.2 Q2：你在项目里负责什么？最有成就感/最有挑战的部分？

推荐答**战斗系统**（§2）：双端共用核心的架构决策（§2.1.1）、移动预测回滚（§2.2.2）、连招树+指令缓存（§2.3.1/§2.4.2）。挑战点话术："最大的挑战是让单机副本和联机对战用同一套战斗逻辑还都好玩——单机要零延迟、联机要防作弊，最终用'一套逻辑两种身份'解决，移动做客户端预测+服务器校验回拉，技能做本地先行+服务器裁决。"

### 8.1.3 Q3：项目架构分几层？怎么解耦的？

三层（§1.2.1）：表现/逻辑/数据；解耦三板斧：① 逻辑层无引擎依赖（双端共享的前提）② 强类型事件总线（模块间零引用）③ 数据服务器权威（客户端只管表现）。可对照 §9.2 通用架构笔记。

## 8.2 战斗系统类（技术深水区）

### 8.2.1 Q4：移动同步怎么做？（必问）

客户端预测 + 服务器校验 + 回滚 + 远端插值，四段话术见 §2.2.2。追问预案：为什么预测（手感）/为什么回滚（作弊与漂移）/误差阈值怎么定（经验值+可配置）/时间戳怎么对齐（心跳时钟同步 §4.5.1）。

### 8.2.2 Q5：技能/攻击是怎么同步的？和移动有什么区别？

移动是**逐帧预测**（连续状态流）；技能是**本地先行+服务器裁决**（离散事件）：按键瞬间本地起手保证手感，发协议给服务器重新校验（CD/消耗/连招窗口），失败打断+回滚 CD（§2.3.3）。区别话术："移动错了慢慢拉回来就行，技能错了要立刻打断——所以技能用'先斩后奏+失败回滚'，移动用'边跑边校验'。"

### 8.2.3 Q6：普攻连招怎么实现的？

连招树（§2.3.1）：树节点=技能段，按键在当前节点子节点里匹配下一段；窗口期判定（上一段收招开始→结束+缓冲）；树由服务器构建下发；变体：窗口连招（首段才有 CD）、蓄力连招、自动连招。画图讲：根→子→孙的树 + 时间轴。

### 8.2.4 Q7：打击感怎么做出来的？

四件套（§2.3.5）：命中时停（HitTimeDilation 局部慢放）、霸体/保护体系（受击状态机+扫地保护防无限连）、交互打断（跳跃打断收招/受击打断技能）、表现层事件驱动（飘字/震屏/音效）。可补充：技能编辑器时间轴配置（无敌帧/位移冲量/吸附）让策划直接调手感。

### 8.2.5 Q8：怎么防止外挂/作弊？

服务器权威四板斧（§2.3.3/§6.2）：① CD/蓝耗/伤害只服务器记账 ② 客户端技能请求服务器重新校验（SvrCheckSkillCond）③ 移动服务器重放校验+位置误差阈值 ④ 玩家数据零本地存档。结论：客户端只是"输入设备+渲染器"，一切值钱的都在服务器。

### 8.2.6 Q9：战斗性能怎么优化？

① 逻辑与渲染分离：逻辑层自洽时钟（50ms 心跳），渲染帧率抖动不影响判定 ② 对象池（子弹/飘字/血条/定时器）③ 虚拟列表（战斗 UI 血条池化 33 个）④ 组件化懒更新（不用的模型不挂更新列表 §1.2.3）⑤ AB 分帧加载（maxItemsPerFrame）。可对照 §6.10 通用优化笔记。

## 8.3 UI 与框架类

### 8.3.1 Q10：UI 框架怎么设计的？为什么不用 MVC/MVVM？（必问）

见 §3.4：层=Canvas+层号=排序；三种层控制器；ViewController 页面流+导航栈+事件总线；面试话术全文在 §3.4.2。

### 8.3.2 Q11：UI 之间怎么通信/刷新？

强类型事件总线 GameEventCenter（Event<T1..T6> 编译期类型安全）：数据变化广播（血条/怒气/编队变化），UI 订阅刷新；层开关广播 LAYER_OPEN_EVENT（主城收起按钮面板）/GUIDE_UPDATED（引导刷新）。补充：context 传参（打开时投递数据 DTO）与工厂回调注入（按钮行为定制）两条同步通道。

### 8.3.3 Q12：返回上一页/回到主页怎么实现？

导航栈+懒重建+路由重置（§3.2.1）：栈存名字不存引用，取栈顶时无实例就按名重建；跳转前 ResetCurLayerRoute(["home_layer"]) 把栈底换成目的地，关闭新页自动弹回主城；被踢/断线清路由防回退到脏页面。

## 8.4 网络类

### 8.4.1 Q13：为什么战斗用 UDP？怎么解决 UDP 不可靠？（必问）

见 §4.4：TCP 队头阻塞 → 战斗高频消息用 UDP → 叠 KCP 拿可靠（ARQ/快速重传/滑窗/拥塞控制，牺牲带宽换延迟）；KCP 跑独立线程，主线程只碰队列。

### 8.4.2 Q14：断线重连怎么做？

三级防线（§4.5.2）：超时检测（仅 TCP 刷新存活）→ 3s 周期软重连（REQ_GLOBAL_ROLE_RECONNECT）→ 8 次/5s 熔断放弃；心跳双通道+时钟同步；恢复后广播事件让界面自检（§7.4）。

### 8.4.3 Q15：RPC 回调怎么设计？

MsgId 关联（§4.3.2）：包头带自增 MsgId，注册回调字典，回包按 MsgId 命中；10s 超时；重要消息 CallServerImport 2s 自动重发 5 次。优点：同 cmd 并发不串包。

## 8.5 工程化类

### 8.5.1 Q16：热更新怎么做的？（必问）

见 §5.1~§5.4：CDN 清单+Hash 差异+双目录；无代码热更（如实说+方案对比 §5.5）。追问"如果做代码热更"→ HybridCLR 推荐方案 §5.5.3。

### 8.5.2 Q17：配置表怎么用的？（数据驱动必问）

Luban 三层（§6.1.1）：生成/partial 扩展/语义接口；外键 _Ref；加工器校验链；运营表服务器热重载。话术："改数值改表、改逻辑改码；表必须配校验管线。"

### 8.5.3 Q18：玩家数据怎么存？（防作弊必问）

服务器权威+零本地存档（§6.2）：登录全量推送+运行期增量合并（NtfType/DelHero）；写操作 REQ→RSP；本地只存登录态/设置缓存。

### 8.5.4 Q19：新手引导怎么做的？（抽象能力考察）

配置驱动+事件循环（§7.1）：GUIDE_UPDATED 广播→监听器各自判定；UI 自动绑定零改动；强引导复制按钮接管点击；组粒度存档。亮点话术在 §7.1.2/§7.6。

## 8.6 通用追问与踩坑

### 8.6.1 Q20：项目里踩过什么坑？怎么解决的？

选 2~3 个真实的：① 引导步骤进度不落盘导致断线重连重复引导（§7.4 取舍）② 确认框 ResetButtonInfo 参数误传导致按钮显隐异常（UI 框架细节 bug）③ GBK/UTF-8 编码混杂导致中文注释乱码、文件读取报错（工程规范问题）④ 弹窗与引导互斥（事件联动解决 §7.2.3）。每个坑讲"现象→定位→修复→教训"。

### 8.6.2 Q21：和队友协作怎么分工/保证质量？

配置驱动让策划自治（改表不发版）；代码规范：region 分区、对称注册约定（UI 事件注册/反注册）；双端共用代码约束（逻辑层不许引用 UnityEngine——架构即规范）；校验链（配置 CfgCheck、协议注册表日志"Not Regist"兜底）。

### 8.6.3 Q22：如果重做这个项目，你会改什么？

① 补 C# 代码热更（HybridCLR，§5.5）② 引导步骤进度落盘（§7.4）③ UI 层考虑引入 MVVM 绑定（复杂度可控的页面）④ 网络层协议生成工具化（MemoryPack 消息手写字段易错）⑤ 统一编码规范（GBK 历史遗留）。显示反思能力。

## 8.7 战斗系统深挖

### 8.7.1 Q23：单人副本为什么不直接纯本地算，还要"模拟服务器"？

单机=联机一致（§1.2.2）：单人副本用本地 RPC 回环（`SingleBattleWorld` 注册本地协议处理器，`IsClientWorld=true`）模拟服务器。好处：① 单机与联机跑**完全相同**的协议与校验路径，逻辑零漂移（联机出的 bug 单机能复现，反之亦然）② 战斗玩法开发时本地即可完整自测 ③ 断线重连天然有兜底（本地战斗世界还在跑，重连只恢复 UI）。代价：多一层协议开销（本地回环成本可忽略）。

### 8.7.2 Q24：战斗世界/战场/角色三级结构怎么设计的？

世界 BattleWorld = 一组关卡（一个副本的多个小关）→ 战场 BattleField = 一场战斗（地图边界/胜负条件/状态机 Init→WaitStart→Battling→Count→End）→ 角色 Actor = 组件容器（13 个战斗组件，§2.1.2）。服务器 50ms 心跳逐层 Tick；世界内多关卡**传送不切场景**（角色移入新战场+广播传送协议）。为什么分三级：世界管跨关流程与玩家数据，战场管单场规则，角色管个体行为——职责与生命周期对齐。

### 8.7.3 Q25：受击状态机怎么设计的（击飞/击倒/扫地/起身）？

受击是一套独立状态（ActorHitState）：冻结/击退/击飞/击倒/起身/拖拽，每个状态 = 一段位移曲线 + 后续规则。设计要点：① 受击类型由命中配置决定（普通/扫地/击飞/拖拽）② 受击位移与重力合成（空中受击可追加连段）③ 倒地角色只能被"扫地技"命中（CheckTargetSweepCanHit）④ 起身保护衔接保护系统（§2.3.5）。面试点：与技能状态机正交——受击可打断技能，技能霸体等级可抗打断。

### 8.7.4 Q26：为什么需要保护机制（黄保/红保/扫地保护）？

格斗游戏的"防无限连"规则层：连段达到阈值后受击方获得保护（黄保→红保），受击时强制脱出连段；扫地保护限制倒地连击次数。没有它：一套最优连招可以无限循环，PVP 变成"谁先手谁赢"，PVE Boss 被无脑连死。面试话术："保护机制是数值平衡的保险丝——连招爽感和对战公平的边界由配置表调节。"

### 8.7.5 Q27：子弹系统怎么实现的？

子弹是技能的载体（§2.3.4）：技能时间轴在指定时间点 CreateBullet → 状态机 Appear→Prepare→Flying→WaitEnd→End；飞行按类型分派（直线/追踪/曲线插值）；命中判定**AABB 粗测 + GJK 精测**；命中后按 TriggerRound 循环施加效果/伤害/Buff/子子弹；支持子弹替换（TryGetBtlletReplace）与牵引。客户端全量模拟子弹只为表现，**命中结果以服务器广播为准**（防作弊）。

### 8.7.6 Q28：命中时停（子弹时间）怎么实现？

命中瞬间给受击方挂时间膨胀（HitTimeDilation，系数由命中配置驱动），受击方与攻击方的逻辑时钟按系数缩放，表现层同步慢放（动画/特效时间轴同系数）。要点：① 时停是**逻辑层状态**（影响判定），不是纯表现 ② 有最短持续时长与恢复曲线（GetDilationLeftMinTime）③ 战斗结束时全场时间膨胀做收尾演出（BattleEndTimeDilation）。

### 8.7.7 Q29：蓄力技能怎么实现？

C2 链路（§2.3.1）：按下 → 本地开始蓄力 + 发 REQ_GAME_ACTOR_STORAGE(Start)；按住保持（长按检测）；松开 → 判定取消区/落点 → 选对应蓄力档位技能本地起手 + REQ(Cancel)；满蓄自动释放。蓄力档位由连招配置 StorageTimeMs 分段（SkillStorageInfo 按蓄力时长推进阶段），服务器校验实际蓄力时长防"瞬满蓄"作弊。

### 8.7.8 Q30：为什么连招树由服务器下发，客户端不自己建？

① 权威性：连招合法性（下一段接什么）由服务器判定，客户端只按服务器给的树查节点，防止客户端篡改连招逻辑（如改出无限连）② 热更性：连招树是配置数据，服务器下发 = 连招调整不用发客户端版本 ③ 一致性：同一英雄在客户端/服务器/回放中树结构一致。代价：进战场时多一次树的同步（随 ACTOR_ENTER_BATTLE 一起下发，无额外往返）。

### 8.7.9 Q31：换人/复活机制怎么做？

换人（备用英雄）：客户端 REQ_GAME_BATTLE_SWITCH_ACTOR → 服务器做角色出战状态切换（旧角色移出 MapOfActor、新角色移入 + BattleSwitchProcess 复制位移/怒气/MP）→ 广播 NTF → 客户端完成控制权移交（InputCommandBuffer 重新绑定新角色）。复活：战场复活组件（RebronComp）按复活数据（次数/道具/费用）决策；玩家死亡后弹复活板（服务器推送复活信息），选择道具复活/放弃；死亡落地时也会再判定一次复活。

### 8.7.10 Q32：怪物/NPC 的 AI 怎么做？

behaviac 行为树（behaviac.Workspace，树由策划用工具编辑导出 bson 蓝图）：NPC/怪物 Update 时走 NpcAIController（AI 控制器）→ 行为树 Tick → 输出移动/技能指令 → 走与玩家相同的移动/施法链路（AI 的操作也是"输入"）。世界/战场 Update 里驱动 `NpcAIBTreeMgr.UpdateWorkSpaceTime()`（AI 工作区时间）。服务器托管（ServerHosting）机制：玩家 300ms 无输入时 AI 接管控制（防挂机），恢复输入交还。面试点：AI 行为与玩家行为同源——AI 不绕过校验，只产生输入。

## 8.8 UI 与框架深挖

### 8.8.1 Q33：层号数字具体怎么设计的？

层号 = sortingOrder（数值越大越靠上）。分组逻辑：低段 2~33 是常规 UI（GamePlay 2 战斗最底 → Dialog 6 主界面 → Popup 19 弹窗 → Tip 30 飘字永远可见 → DisconnectPopup 33 断线最高弹窗）；高段 40~65 是全局特效/遮挡（Transition 40 转场 → Waiting 50 菊花 → **Background 60 其实是上下装饰边框**（前景装饰）→ **Mask 65 全屏透明 Image + RaycastTarget 纯输入拦截**）。层号间留空隙，层内子 Canvas 用"层号+2/+3/+4"偏移不越层（§3.2.3）。

### 8.8.2 Q34：转场怎么实现？怎么挡住输入？

TransitionLayer（§3.2.2）：`Transition(callback)` = 开转场动画（粒子+Animator，时长读动画状态而非硬编码）→ **打开 Mask 层（65 层全屏透明 Image+RaycastTarget）拦截一切点击** → 黑幕中执行 callback（切场景/切状态）→ 播退场动画 → 关 Mask。防重入标志 _transitioning；切场景用 TransitionLayer（读动画时长），战斗内区域传送用 SceneTransitionLayer 变体（固定 0.5s）。

### 8.8.3 Q35：列表（GridView/LoopListView）怎么做虚拟化？

对象池 + 可视区间 + 分帧加载：只实例化视口内 [start,end] 的 Item（滚动时按需创建/回收，Item 复用队列）；maxItemsPerFrame 分帧实例化防单帧卡顿；LoopListView 支持变尺寸、多 prefab 分类池、运行时换 prefab/改尺寸重排。控制器基类用模板方法：子类只实现 GetItemPrefab/GetItemCount/OnItemShown。战斗血条（怪物血条池化 33 个）是同类思路。

### 8.8.4 Q36：弹窗和引导怎么协调互斥？

引导监听器弹出前检查：Dialog 层有弹窗（NoPopLayer==false）→ 不弹引导；弹窗关闭 → LayerManager 广播 GUIDE_UPDATED → 引导监听器刷新尝试弹出（§7.2.3）。设计本质：**弹窗是更高优先级的事件源**，引导永远等弹窗清场——用事件联动而非代码互相调用，谁都不依赖谁。

## 8.9 网络与协议深挖

### 8.9.1 Q37：为什么用 MemoryPack 序列化？

MemoryPack 是新一代二进制序列化（比 MessagePack 更快、零分配理念，支持多态 Union）。项目里：消息类 `[PKG(命令字)]` 特性 + `[MemoryPackUnion(id, typeof(X))]` 把全部消息注册进多态联合（id 与协议命令字一致）→ 解码端 `MemoryPackProtoDecode<T>` 按命令字直接反序列化。对比：protobuf 需要 .proto 生成代码（项目有历史 protobuf 残留，已并存），MemoryPack 直接用 C# 类型标注更贴近 Unity 项目。面试话术："二进制序列化 + 多态联合，协议加字段向后兼容（新字段默认值），性能与可读性平衡。"

### 8.9.2 Q38：登录流程完整讲一遍？

HTTP 拉服务器列表 → 选服（随机验证服）→ TCP 连验证服 → 认证（响应带回代理服地址）→ 连代理服 → 拉角色列表 → 选角登录 → 服务器全量推送角色数据 → 客户端进入主城/断线重连判定（§4.2）。为什么两段式：验证服是轻量认证服务（可水平扩容、挡恶意连接），代理服是长连接网关——认证与承载分离，安全与负载各自优化。

### 8.9.3 Q39：时钟同步怎么做？为什么重要？

心跳回包带服务器时间戳 → 客户端算 `TimeHelper.DeltaTime = 服务器时间 - 本地时间`（持续校准）。为什么重要：移动预测、技能时间轴（抬手/收招时长）、CD 计算、回放都是"时间敏感"逻辑——双端时钟不一致会导致"客户端看到技能放出去了、服务器判定超时"。面试点：不用 NTP 级精度，心跳校准足够（秒级误差内的相对时间差才是关键）。

### 8.9.4 Q40：本地回环 RPC 是什么？（单人战斗的关键）

单人战斗里客户端既发请求又收请求：`NetworkMgr.GetRpcClient().AddLocalMemoryPackListener` 把本应发往服务器的协议注册到本地处理器——REQ 发出后不进网络，直接进本地监听函数（模拟服务器处理并回 RSP/NTF），表现层完全无感。好处：输入/技能/换人代码一条路径，单机联机零分支（§2.1.1）。

## 8.10 工程与工具链

### 8.10.1 Q41：AssetBundle 打包流程什么样？

编辑器打包工具（Editor/BundleTool）：按资源目录组织 AB → 构建清单（资源名→BundleName+Hash+依赖+是否基础资源）→ 生成带 Hash 的文件名（bundleName_hash.dat，LZ4 压缩）→ 打包时输入热更版本号（fixVersion/fixVersionCode 弹窗）→ 输出到 CDN。运行时按 §5.3 七步检查更新。要点：**Hash 是差异更新的基石**（内容哈希，同名同内容不重复下载）。

### 8.10.2 Q42：技能编辑器是干嘛的？

可视化时间轴编辑器：策划在编辑器里排技能（前摇/释放/收招时长、子弹发射点、无敌帧、位移曲线、受击盒）→ 导出 JSON → 运行时 `GameSkillEditorCfgMgr` 加载解析为 `SkillThirdCfg`（§6.1.5）。价值：① 技能制作去代码化（策划自治）② 时间轴数据可实时预览/热重载（编辑器导出后 ReloadCfgByEditor 刷新）。

### 8.10.3 Q43：日志与埋点体系？

三层：① 运行时错误日志：GameLogManager 监听核心/逻辑/网络错误 → Debug.LogError（ENABLE_LOG_REDIT 宏控制）② 业务埋点：ThirdPlatLogHelper → JSON → NTF_GAME_CLIENT_LOG_REPORT 上报服务器（引导/英雄/背包/任务/战斗 20+ 类事件，§6.3）③ 战斗日志：battle_start_log/战斗结算记录（服务器侧落库，用于对账/仲裁）。要点：埋点数据模型序列化类化（GuideLog/BattleStartLog），上报走游戏服务器而非第三方 SDK。

### 8.10.4 Q44：客户端崩溃/异常怎么收集？

（结合项目实际答通用方案）错误日志监控（GameLogManager 三类错误监听）+ 第三方崩溃 SDK 预留位（项目里 SDK 初始化被注释，可讲"接入崩溃 SDK + 日志上抛"的通用做法）+ 关键流程日志埋点（启动管线分步 LoadStepWatch 计时，定位卡死步骤）+ 服务器侧协议日志（对账客户端行为）。诚实说明：项目以错误日志+埋点为主。

## 8.11 性能与优化专项

### 8.11.1 Q45：战斗卡顿怎么排查？

排查链：Profiler 定位（CPU/GPU/内存）→ 逻辑层与渲染层分离定位（逻辑 Tick 用自洽时钟，帧率低但判定不错——先确认是"渲染卡"还是"逻辑卡"）→ CPU 侧查：GC 峰值（对象池/装箱）、UI 重建（Canvas 重组）、配置查询热点（DataMap 缓存）、协议解码开销；GPU 侧查：DrawCall（合批/图集）、Overdraw、特效峰值。优化三板斧：对象池、分帧、降特效档（战斗画质分级 myVfxValue 等设置）。

### 8.11.2 Q46：GC 优化具体做了什么？

① 对象池（子弹/飘字/血条/定时器 TimerItem）② 移动包复用（SaveMove 池化）③ 事件参数复用（结构体事件/缓存 StringBuilder，CommonFunc.CacheText）④ 避免装箱（泛型事件 Event<T> 而非 object 参数）⑤ 字符串拼接改格式化缓存（GBK 注释乱码就是历史编码问题，顺带可提编码规范）。面试点：先 Profiler 找热点再优化，不臆测。

### 8.11.3 Q47：UI 层做了哪些性能设计？

① **层=Canvas 天然合批友好**：每个界面独立 Canvas，界面内元素合批、界面间互不污染（Canvas 重组只影响本层）② 怪物血条池化 ③ 虚拟列表（§8.8.3 Q35）④ 图片图集（SpriteAtlas 按需加载，AssetManager 注册 atlasRequested）⑤ 伤害飘字对象池 ⑥ 分帧加载 AB。面试点：层号设计不只解决遮挡，还隔离了 UI 重建开销。

### 8.11.4 Q48：包体优化怎么做？

① 配置二进制化（Luban 238 张表 → bytes，比 JSON/CSV 小）② AB LZ4 压缩（.dat）③ 资源按需打包（PreLoadAbList 只预加载首屏必需）④ 热更资源不占包体（放 CDN）⑤ 图集合并减少文件数。可扩展讲：音频压缩格式、纹理压缩格式（ASTC 等）、剔除未用资源。

### 8.11.5 Q49：多机型/分辨率适配怎么做？

① 画质分级设置（分辨率缩放 SetResolutionScale/帧率/特效档，服务器同步）② UI 全屏拉伸（层 Canvas 锚点全屏 + 界面内自适应）③ 相机视距设置（camerFocallengthValue 映射 orthographicSize）④ 战斗逻辑与分辨率解耦（逻辑坐标独立于屏幕坐标）。

## 8.12 系统设计场景题

### 8.12.1 Q50：如果让你设计一个新英雄，流程是什么？

全配置流：① 数值表（属性池/成长/品质）② 技能编辑器做技能时间轴+子弹+受击配置 ③ 连招树配置（普攻段数/窗口期/技能键位）④ 模型/动画/特效资源 ⑤ 引导/图鉴/解锁条件挂接 ⑥ 校验链（CfgCheck）跑通 → 测试关卡验证。零代码（除非新机制：新状态/新 Buff 效果才需要扩展组件）。

### 8.12.2 Q51：如果加一个新玩法模式（如新副本类型）？

复用战场工厂：① 副本配置（DungeonConfig/WorldCfg 关卡列表）② 新增 BattleField 子类（继承 BattleFieldBase 覆写 OnInitAfter/OnBattleEnd 等钩子，玩法规则：胜负/刷怪/事件）③ 新增 DungeonController（BattleFieldType → 工厂注册）④ 战斗外配套（入口 UI/匹配流程/结算层 context 分派）。项目已有 20+ 种 BattleField 子类，新玩法=新子类+配置（§2.1.1）。

### 8.12.3 Q52：设计一个排行榜系统？

项目思路（NetRankMsg/PvpRank 已有）：服务器排名（分数变化时增量更新排名，避免全量排序）+ 客户端只拉榜单页（Top N + 自己名次，RSP 懒加载）+ 赛季制（赛季数据组件 RoleSeasonDataComponent）+ 展示层走通用榜单 UI。要点：排名计算放服务器（防作弊），客户端只做展示与上报。

### 8.12.4 Q53：设计聊天系统（敏感词怎么处理）？

项目有 NetChatMsg + SensitiveHelper（TbSensitiveWords 表）：敏感词**服务端过滤**（客户端预过滤只是体验优化，权威在服务器）+ 分频道（世界/好友/公会）+ 离线消息 + 聊天 UI 用 NestedController 复用。要点：过滤规则配置化（敏感词表可热更），防绕过（全角/空格/同音）靠服务端词库迭代。

### 8.12.5 Q54：设计红点系统？

项目思路（RedPointData 随角色数据下发 + CommonRedPoint 组件）：红点 = **服务器计算的状态位**（哪些入口有未领/未读），登录数据带 RedPointData；客户端红点组件只负责显示/隐藏（挂在按钮上）；入口红点树（父节点聚合子红点）；变化时服务器推送刷新。要点：红点判定不在客户端算（多端一致+防状态不同步），只做展示。

### 8.12.6 Q55：线上"战斗不同步"怎么排查？

排查三板斧：① 战斗日志回放（项目有 ReplayViewer 回放模型 + 战斗日志落库）复现 ② 双端时间戳与协议比对（预测/回滚日志：客户端 SaveMove vs 服务器校验结果）③ 版本核对（AB Hash/配置版本不一致是不同步第一嫌疑：热更后客户端资源与服务器配置不同步）。根因常见：浮点误差累积（逻辑层统一定点/整数计算可避免）、配置版本不一致、状态机边界条件。预防：逻辑双端共用代码（§1.2.2）+ 服务器校验兜底。

## 8.13 行为面与复盘

### 8.13.1 Q56：你最有成就感的一件事？

推荐答法（STAR）：S 情境（战斗系统同步问题——单机联机要一致）→ T 任务（移动/技能同步方案）→ A 行动（预测+校验+回滚架构设计、本地回环模拟、连招树+指令缓存）→ R 结果（手感达标/单机联机行为一致/可测试性提升）。突出"架构决策带来系统性收益"而非堆功能。

### 8.13.2 Q57：和策划/同事有分歧怎么办？

框架：先对齐目标（体验指标 vs 实现成本）→ 数据说话（能快速验证的方案先做原型/可配置开关）→ 求同存异（配置化把决策权留给策划：技能参数/引导步骤都表驱动）。实例：数值平衡分歧 → 全部表驱动 + 测试关卡，策划自己调。

### 8.13.3 Q58：你平时怎么学习/跟进新技术？

结合项目：跟进 Unity 版本与官方方案（HybridCLR/DOTS 等热更与性能方案，§5.5）、读开源（KCP/Luban/MemoryPack 源码级理解）、以问题驱动（项目遇到的同步/热更问题 → 调研业界方案 → 落地）。

### 8.13.4 Q59：为什么看机会/职业规划？

（按个人实际情况，给框架）技术方向：继续深耕 Unity 客户端 + 向引擎/架构方向（渲染/工具链/性能）延伸；选择理由：技术栈匹配 + 项目类型匹配 + 成长诉求。避免负面评价前司。
