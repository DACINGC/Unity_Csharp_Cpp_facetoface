# 三、UI 框架

> 本章讲项目自研 UI 框架：层管理（层=Canvas、层号=排序）、三种层控制器、生命周期管线、导航栈与路由、弹窗分级体系，以及面试必问的"为什么不用 MVC/MVVM"（§3.4）。

## 3.1 层管理框架（Layer Manager）

### 3.1.1 核心设计：层 = Canvas，层号 = sortingOrder ★★★

- 每个"层"是一个**全屏 Canvas + GraphicRaycaster**（LayerManager 动态创建），**层号直接就是 Canvas.sortingOrder**——打开界面不用管 z 序，选对层号天然正确遮挡。
- 层号分组（`LayerTag`）：GamePlay(2 最低，战斗 UI) / Login(3) / Dialog(6 主界面) / Loading(11) / Popup(19 弹窗) / Guide(29) / Tip(30 飘字) / Transition(40) / Waiting(50) / **Mask(65 全屏透明 Image + RaycastTarget，纯输入拦截)**。
- 每层预分配一个"内容组织策略"（层控制器），业务只关心"放哪层"。

### 3.1.2 三种层控制器（策略模式）

| 控制器 | 行为 | 典型层 |
| --- | --- | --- |
| DefaultLayerController | 单实例覆盖：新内容直接销毁旧的 | Tip（飘字即用即毁，连发只显示最后一条）/ Chat / Guide |
| StackLayerController | **栈**：压栈时旧层只隐藏不销毁，关栈顶自动回显下层；支持路由重置 | Dialog / Popup / GamePlay |
| UnCloseStackLayerController | 栈但实例常驻不销毁 | LayerPopup（系统解锁）/ InvitePopup（邀请） |

- 附加机制：`LoadContentSingleton<T>` 单例层（同 key 只保留一个实例，重复请求置顶复用 + 加载防重入）。

### 3.1.3 生命周期管线（模板方法钩子 ★★）

```
打开：静态工厂 Create → LoadContent（AssetBundleKey 特性 → prefab key → 同步加载实例化）
  → Awake（注册按钮）→ Controller.OnNewContent → OnCreate(context) → OnShown
  → OnUIEnable（注册事件/AddClick + 自动开 Blurs 遮罩）→ 工厂 SetUp/Init（业务初始化）→ Start
关闭：layer.Close → Controller.CloseContent → OnUIDisable（反注册）→ OnClose（Destroy）
  → Unity OnDestroy（最终清理：RemoveClick/RemoveListener/Cancel CTS）
栈内显隐：压栈时旧层 OnUIDisable+OnHide（不销毁）；出栈回显 OnShown+OnUIEnable
```

- **对称约定**：Awake 注册的按钮在 OnDestroy 移除，OnUIEnable 注册的事件在 OnUIDisable 移除——栈里的层会反复显隐，监听必须跟着显隐走否则泄漏/误响应。
- 弹窗基类 `PopupLayerContent`：重写进出场（缩放 OutBack 入场 + 遮罩淡入；退场动画播完才 Destroy）——**框架管动画，业务只填内容**。

## 3.2 导航与弹窗

### 3.2.1 导航栈 + 路由重置 + 懒重建（返回上页的实现 ★★）

- 栈里存**名字不存引用**；`CurrentContent` 取栈顶时字典没有实例 → 按名字当场 `LoadContent` 重建（**懒加载**）。
- `ResetCurLayerRoute(["home_layer"])`：清栈重设路由（栈底=主城）→ 再压新界面 → 关闭新界面时弹栈 → 懒加载回到主城——这是"跳转前先把栈底换成目的地"的页面跳转范式；被踢/断线用 `ResetCurLayerRoute([])` 清路由防回退到脏页面。

### 3.2.2 弹窗分级体系

| 类型 | 层 | 机制 |
| --- | --- | --- |
| 短提示 MessageTip | Tip(30) | 覆盖式、DOTween 动画自动销毁（Fade≈2s）；文本"先查多语言表，查不到原样显示"双模式 |
| 确认框 MessageLayer | Popup(19) | 压栈叠放；`ShowMessageLayerWithSystemTipsID(ID)` → 配置表（正文支持 `string.Format` 占位符、Type==3 显示取消）→ 回调 `Action<bool>` |
| 系统解锁 | LayerPopup(14) | 不可一键关闭；可缓存延迟弹出（任意层 OnShown 时补弹） |
| 断线/全局 | DisconnectPopup(33) | 最高弹窗 |
| 转场 TransitionLayer | Transition(40) | `Transition(callback)`：黑幕 → Mask 开（挡输入）→ 执行切换 → 淡出；时长读 Animator |

### 3.2.3 层内子 Canvas 排序约定

- 基准 = 所属层号，偏移不越层（层号间留有空隙）：**+2 常规子面板（最常见）、+3 二级弹层、+4/+5/+6 最高浮层**、+1 小浮件、粒子叠在层号上。

## 3.3 业务层开发约定

### 3.3.1 Create 静态工厂模式（一个 prefab 多个变体）

```
public static HeroBagLayer Create(...)
{
    var layer = LoadContent(LayerTag.Popup, "hero_bag_layer") as HeroBagLayer;
    layer.SetUp(...);                 // 业务参数
    layer.AddClickOk(callback);       // 注入回调（按场景定制）
    return layer;
}
```

- 加载与初始化分离：LoadContent 管框架生命周期，SetUp/Init 管业务数据；HeroBagLayer 一个 prefab 有 8 个 Create 变体（选英雄/武魂殿/组队/公平模式…）。
- **重入保护**三种：`IsLayerContentExist<T>()`（已开则拦截）、`LoadContentSingleton`（置顶复用）、栈内按名去重。
- **context 传参**：每次显示重新投递（常用 DungeonController/DTO/页签枚举），层在 OnCreate/OnUIEnable 里 `context is Xxx` 类型判断消费。

### 3.3.2 NestedController 嵌套控制器（子面板复用）

- **Layer 管"页"，NestedController 管"可复用子面板"**：普通 MonoBehaviour（非 LayerContent），生命周期跟随父层，暴露 `SetUpAll/SetData/RefreshXxx` 由父层调用；需要排序时传父层号做内部 Canvas 排序（layer+2）。
- 例：英雄信息面板 `HeroAllInfoNestedController` 被编队/选英雄/房间三处复用，内部再嵌技能信息子控制器。

## 3.4 为什么不用 MVC/MVVM（★★★ 必问）

### 3.4.1 架构定位：ViewController 模式 + 事件总线

- 本框架**没有采用严格 MVC/MVP/MVVM**，也不是第三方框架；本质是 **iOS UIKit 风格**：`LayerContent` ≈ UIViewController（视图+交互逻辑一体、配置式生命周期），层控制器 ≈ UINavigationController（导航栈）。
- Model 与 View 之间的解耦靠**观察者事件总线**（`GameEventCenter` 强类型事件）：Model 发事件（血条/怒气/引导/层开关），View 订阅刷新——这是"MVC 思想的事件版"（Model 不依赖 View，View 与 Controller 合并）。

| 模式 | 符合度 | 说明 |
| --- | --- | --- |
| MVC | 一半 | 有 Model 分离；View 与 Controller 合并（LayerContent 同时管渲染与交互） |
| MVP | ❌ | 无 Presenter 层 |
| MVVM | ❌ | 无 ViewModel、无数据绑定，刷新靠手动 SetUp + 事件监听 |

### 3.4.2 面试话术（为什么这么设计）

"手游 UI 本质是**页面流**（打开/关闭/返回），导航栈天然匹配，比 MVC 三件套务实；每个页面一个类（prefab+Layer 脚本）出活快、学习成本低；Unity 组件式机制本身不鼓励纯 View。事件总线补足了 MVC 的通信短板（页面间数据联动不互相持有引用）。代价是页面类容易膨胀、刷新手动易漏、不可单测——这是务实与纯正的权衡。如果面试官追问 MVVM：数据绑定对手游收益低（表单类 UI 少）、调试难，而页面流场景用不上。"
