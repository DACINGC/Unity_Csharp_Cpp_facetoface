【2】Canvas的三种渲染方式
Screen Space - Overlay（屏幕空间 - 覆盖）​：
UI ​直接绘制在屏幕最上层，不受摄像机影响。
UI 元素始终覆盖在场景和摄像机内容之上。
​无需关联摄像机，自动适配屏幕分辨率。
适用场景：简单的 2D UI（如菜单、HUD 血条）。需要 UI 始终可见且不与 3D 场景交互的情况。

 Screen Space - Camera（屏幕空间 - 摄像机）​
UI ​通过指定摄像机渲染，可以应用后期处理效果（如模糊、景深）。
UI 的尺寸和位置会随着摄像机视口变化而自动调整。
需要手动关联一个 ​摄像机（Camera）​。
​适用场景：需要 UI 与摄像机视角联动的场景（如跟随摄像机的动态 UI）。需要为 UI 添加特殊视觉效果（如屏幕边缘的镜头光晕）。

World Space（世界空间）​
UI ​作为 3D 物体存在于场景中，可以自由调整位置、旋转和缩放。
必须手动设置 UI 的 RectTransform（位置、尺寸等）。
需要关联一个 ​摄像机​ 来渲染 UI。
​适用场景：3D 场景中的交互式 UI（如游戏内的显示屏、角色头顶的对话框）。VR/AR 项目中需要 UI 与真实空间对齐的情况。

【7】FixedUpdate为什么会按照固定的时间步长执行，当Update受影响时，FixedUpdate会受影响吗
Unity 内部通过累积时间触发 FixedUpdate
每帧根据真实时间（Time.unscaledDeltaTime）累积到 Fixed Time 计数器。
当 Fixed Time 超过 fixedDeltaTime 时，调用一次 FixedUpdate 并扣除一个步长。
重复直到 Fixed Time 不足一个步长。

Update的调用与实际帧率有关
当实际帧率发生波动时，Update会收到影响，FixedUpdate不会
当修改Time.timescale参数时，都会发生影响

【11】Drawcall是什么，为什么减少Drawcall能提升性能，为什么有时候减少了Drawcall性能没有提升
Drawcall 即绘制调用，是 CPU 向 GPU 发送的用于指示渲染特定几何数据的指令。

提升性能：
对CPU：每次发起 Drawcall 时，CPU 都要进行一系列的状态设置和数据提交，传输到 GPU 显存中（渲染状态，顶点数据、索引数据）
对GPU：GPU 具备强大的并行计算能力，过多且零碎的 Drawcall 会使得 GPU 频繁地在不同的渲染任务间切换，造成 GPU 资源的浪费

没有提升性能：
内存压力增大：批处理技术虽然能够合并多个渲染对象从而降低 Drawcall 数量，但也会带来内存占用的增加。
材质和着色器复杂度过高：

【12】渲染管道
定义了图形数据从输入（如 3D 模型的顶点、纹理等信息）到输出（屏幕上的像素）所经历的完整流程
阶段：
1.应用阶段：
开发者控制：确定每一帧中需要渲染哪些游戏对象（相机参数等）
数据输出：将输出一批需要被渲染的几何数据（如模型的顶点数据、索引数据等）
2.几何阶段：
对模型顶点做模型、视图、投影变换；进行顶点着色、裁剪等操作，将 3D 数据转为适合屏幕显示的 2D 数据形式。
3.光栅化阶段
把顶点组装成图元（如三角形），将图元转换为屏幕像素，计算像素属性信息生成片元。
4.像素处理阶段
对片元精细着色计算；进行深度测试确定可见性，通过混合实现透明等效果，最终确定像素颜色写入帧缓冲区 。

【扩展Unity 中的渲染管道类型】
内置渲染管道：Unity 早期版本默认的渲染管道，它提供了一套相对通用和基础的渲染功能，

[1].线程、进程、协程的区别
进程
是操作系统分配资源的基本单位，每个进程都有独立的内存空间和系统资源。
特点：
独立性：进程之间相互隔离，一个进程崩溃不会影响其他进程。
资源开销：进程的创建、切换和销毁开销较大。
通信方式：进程间通信（IPC）需要通过管道、消息队列、共享内存等机制。

线程
是进程内的执行单元，一个进程可以包含多个线程，所有线程共享进程的内存空间和资源。
特点：
轻量级：线程的创建、切换和销毁开销较小。
共享资源：线程之间共享进程的内存空间，但需要同步机制（如锁）避免竞争条件。
通信方式：线程间通信可以直接通过共享内存。

协程
是一种用户态的轻量级线程，由程序控制调度，而不是操作系统。
特点
协作式调度：协程主动让出执行权，而不是被操作系统强制切换。
低开销：协程的创建和切换开销极小。
单线程内并发：协程在单线程内实现并发，无需考虑线程安全问题。

[2].DFS 和BFS的区别
广度优先遍历（BFS）：逐层遍历，先访问根节点，再访问其所有相邻节点
使用队列（FIFO）来存储待访问节点
在最坏情况下（如完全二叉树），空间复杂度为 O(n)，n 是节点数。
适用于寻找最短路径、层次遍历等场景

深度优先遍历（DFS）：沿着一条路径尽可能深入，直到无法继续为止，再回溯并探索其他路径
使用栈（LIFO）来存储待访问节点，递归实现时利用系统调用栈
空间复杂度取决于树或图的深度，最坏情况下为 O(h)。h 是最大深度。
适用于拓扑排序、连通性检测、路径搜索等场景。

【1】TCP和UDP
TCP：
面向连接，
可靠传输：发送方超时未收到 ACK 则重传，序列号：保证数据按顺序重组。
流量控制：通过滑动窗口协议动态调整发送速率，避免接收方缓冲区溢出。
拥塞控制：根据网络状况调整发送速率，算法包括慢启动、拥塞避免、快速重传、快速恢复
全双工通信：支持双向数据传输（客户端和服务器可同时收发数据）。

UDP：
无连接：
不可靠传输：不保证数据到达目的地，无 ACK 确认和重传机制。
无顺序控制：
轻量高效：头部仅 8 字节（TCP 头部 20 字节），无复杂控制机制，传输延迟低。
支持广播和多播：可向多个接收方同时发送数据。

【TCP如何确保可靠】
1.序列号与确认机制：
序列号：标识该报文段第一个字节的序号
确认号：接受方收到之后会发送确认收到，接收方未收到会重新传输数据
2.重传机制：
​超时重传
快速重传：接收方收到乱序的报文段，会发送重复的ACK。发送方收到3个重复ACK后，立即重传丢失的报文段。
3.流量控制：
滑动窗口：接收方通过窗口大小字段告知发送方其当前可接收的数据量。发送方根据窗口大小动态调整发送速率，避免接收方缓冲区溢出。
4.拥塞控制：
慢启动：建立连接后，发送方从1个MSS（最大段大小）开始，每收到一个ACK，窗口大小翻倍，直到达到阈值。
拥塞避免：当窗口大小达到阈值，会收到一个ACK，窗口大小线性增加
快速恢复：发生拥塞后，窗口大小减半，进入快速恢复阶段，避免窗口大小骤降

[1].状态同步和帧同步
状态同步
定义：服务器定期将游戏世界的完整状态发送给客户端，客户端根据接收到的状态更新本地游戏画面。
工作原理：
服务器计算所有游戏逻辑，定期将游戏状态（如玩家位置、血量等）发送给客户端，客户端根据接收到的状态更新本地显示。
优点：
实现简单，逻辑集中在服务器端。安全性高，客户端难以作弊。
缺点：网络带宽消耗大，尤其在状态复杂时。客户端响应延迟较高，影响体验。
适用场景：MMORPG、回合制游戏等对实时性要求不高的游戏。

帧同步
定义：服务器只同步玩家的输入指令，客户端根据相同的初始状态和输入指令独立计算游戏逻辑，确保各客户端状态一致。
工作原理：客户端将玩家输入发送给服务器。服务器将输入广播给所有客户端。各客户端根据相同的初始状态和输入指令独立计算游戏状态。
优点：网络带宽消耗低，只同步输入指令。客户端响应速度快，体验流畅。
缺点：实现复杂，需确保各客户端逻辑一致。安全性较低，客户端可能作弊。
适用场景：实时性要求高的游戏，如MOBA、RTS等。

1.什么是点乘、什么是叉乘，他们的实际应用？
点乘：
定义：点乘是两个向量的标量积，结果是一个标量
几何意义：点乘的结果表示两个向量的相似程度
如果 A 和 B 方向相同，点乘为正。
如果 A 和 B 方向相反，点乘为负。
如果 A 和 B 垂直，点乘为 0。
实际应用：计算夹角、投影长度
光照计算：算光照强度（如漫反射）。
判断方向：通过点乘的正负判断两个向量的方向关系。
叉乘：
点乘：叉乘是两个向量的向量积，结果是一个向量
几何意义：叉乘的结果是一个垂直于 A 和 B 的向量，其长度等于两个向量构成的平行四边形的面积。
实际应用：计算法向量：判断方向：叉乘的结果可以判断两个向量的相对方向（顺时针或逆时针）。
物理中的力矩：计算平行四边形面积：

归一化：没有大小，只有方向的向量

【4】元表中的__index、__newindex、__call、__tostring、rawset、rawget是什么
__index：如果通过setmetatable设置了元表，获取当前表没有的变量，就会去元表的__index寻找该变量。
__newindex：赋值当前表中没有的变量，则会调用__newindex。
__call：执行表中传入的参数为数值时，则会调用__call
__tostring：将当前表赋值给其他对象时，则会调用__tostring
