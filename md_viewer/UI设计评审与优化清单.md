## 二、可优化的设计点（现有功能升级）

1. 目录滚动跟随（scroll-spy）+ 阅读进度条
2. 文档内查找（Ctrl+F）
3. 分享链接带小节锚点（`?path=…&anchor=…`）

5. 掌握度标记交互：右键清除、marks 带时间戳
6. 间隔重复复习（SM-2/艾宾浩斯）

8. 最近打开列表
9. 文件变更自动感知（mtime 探活提示刷新）
10. 编辑分栏实时预览 + 新建/重命名/删除接口
11. 搜索升级：拼音首字母、模糊容错、搜索历史、范围切换、多关键词
12. 文件列表：目录分组折叠、排序
13. TOC 树折叠
14. 性能：会话内缓存文档内容
15. 移动端（≤700px 工具轨隐藏）加「⋯」溢出菜单收纳主题/抽题/打印/帮助
16. 快捷键扩展：Alt+←/→ 切文件、R 抽题

## 本轮：界面高级感 + 交互补全 + 冗余收敛（已实施）

> 评审结论：先立设计系统（令牌），再按「一个功能一个入口」收敛，最后补交互与状态。`renderer.js` 与 `mdviewer.py` 未改动，仍为零依赖单文件前端。

### 一、设计系统（`index.html` `:root`）

- 深色默认：冷调中性基底（`--bg #0e1013` / `--panel #14171b`）、发丝描边（`--hairline`）、玻璃粘性栏（`--bg-glass` + `--blur`）、强调色渐变（`--accent-grad`）、三级投影（`--shadow-1/2/3`，`--shadow` 保留为 3 的别名）、统一圆角（`--r-sm/md/lg/pill`）、动效令牌（`--ease` + `--dur-1/2/3`）、焦点环（`--focus-ring`）、语义色三件套（`--success/warning/error-soft`）、阅读测宽 `--doc-measure: 900px`
- 浅色主题逐项对照，并修掉此前的浅色残色：滚动条、`::selection`、表格斑马纹（`--row-stripe`）、代码块描边（`--code-border`）、面包屑背景、文件类型图标（`--icon-*`）、热力图色阶（`--heat-1..4`）
- `<head>` 内新增极小主题引导脚本：首帧前设好 `data-theme`，消除明暗切换闪屏
- 全局 `:focus-visible` 焦点环与 `:active` 按压反馈；`@media (prefers-reduced-motion: reduce)` 关闭动画，`scrollBehavior()` 让平滑滚动退化为瞬时定位

### 一、§ 引用的根因修复（影响最大）

- **问题**：`sections` 是**全局**编号映射且"首现优先"，而两套笔记并行使用 1.x~8.x 编号、有 **94 个重号** → 项目层 **63.7%** 的 `§` 引用跳到通用层同号章节（项目索引 19 个唯一引用只有 4 个正确）。
- **修法**：服务端新增 `sectionsByFile` / `sectionsByLayer`，并把**文档级章号**（`§9` → 第 9 篇首标题）登记进层映射；前端按 **本文件 → 本层 → 全局** 三级解析，且全局兜底只允许带点编号。
- **配套**：`renderer.js` 标题 id 增加**文件内去重**（`-2`/`-3`），与服务端 `assign_anchors` 对齐；`search_text` 复用同一套锚点算法（原先是第三份手写实现）。
- **验收**：新增 `md_viewer/verify_sections.js`——全库 **294 处引用 0 失败**，项目索引 19 个唯一引用全部落到本层。

### 二、写接口安全与前端健壮性

| 修复 | 说明 |
| --- | --- |
| **CSRF 防护** | 新增 `_origin_allowed()`：写接口要求 `Origin`/`Referer` 为本机同端口 + `Content-Type: application/json`，不满足返回 403；校验先于业务逻辑（被拒请求不改文件） |

## 后续增量：首页两卡等高（2026-10-09）

- **问题**：`.home-grid` 用了 `align-items: start`，两张卡各按自身内容高度渲染 ——「待复习」6 条、「最近打开」8 条时就一高一低参差。
- **修法**：改为 `align-items: stretch`（条目少的一侧补齐到与另一侧同高），并给两卡内的列表加同一 `max-height: 216px` + `overflow-y: auto`，条目再多也不会把卡片撑长（超出在卡内滚动，滚动条样式沿用全局）。作用域限定 `.home-grid .workbench-list`，复习工作台那张全量清单不受影响。
- **测试**：`verify_browser.js` 新增「首页两卡等高」运行时断言 —— 这是布局行为，`test_app.js` 那类静态字符串断言测不出来。
  同时给该脚本加了 `Emulation.setDeviceMetricsOverride(1440×900)`：**headless Chrome 默认窗口只有 800px 宽**，会直接落进 `.home-grid` 的单列降级分支，那时两卡各占一行、行高互相独立，这个契约根本测不出来（首轮就是这样误报的 `[112, 286]`）。
