# 七、图形学与数学基础

## 7.1 向量

### 7.1.1 点乘（内积）

- 定义：两个向量的标量积，结果是**标量**：`a·b = |a||b|cosθ`。
- 几何意义：表征两个向量的**相似程度/夹角**；b 向量在 a 向量方向上的**投影**。
  - 方向相同 → 点乘为正；方向相反 → 为负；垂直 → 为 0。
- 实际应用：
  - 计算夹角、投影长度；
  - 光照计算：漫反射 `max(0, N·L)`；
  - 判断方向关系（正负）、判断前后（敌人是否在面前）。

### 7.1.2 叉乘（外积）

- 定义：两个向量的向量积，结果是**向量**：`a×b = |a||b|sinθ·n`（n 为垂直于 a、b 所在平面的单位向量）。
- 几何意义：结果垂直于原两向量构成的平面；长度等于两向量构成的**平行四边形面积**；方向由**叉乘的定则**决定——数学惯例（右手坐标系）下用右手定则，而 **Unity 是左手坐标系，`Vector3.Cross` 遵循左手定则**（与 §7.3 的坐标系说明一致）。跨引擎时符号可能相反，这是常见坑。
- 实际应用：计算法向量；判断两向量相对方向（顺时针/逆时针）；物理中的力矩；计算面积。

### 7.1.3 归一化（标准化）

- 归一化：只保留**方向**、把长度变为 1 的向量（不关心大小、只关心方向时使用，如法线、光方向）。

### 7.1.4 实际应用：如何判断一个物体在自己的前后左右

**核心思路**：先求出"自身 → 目标"的方向向量 `dir = target.position - self.position`，再与自身的朝向向量做点乘/叉乘判断（`dir` 建议先归一化，并忽略 Y 分量投影到水平面，避免俯仰角干扰左右判断）。

**① 判断前后——点乘（cosθ 的符号）**

```
dot = Vector3.Dot(self.forward, dir)
```

| dot 取值 | 位置关系 |
| --- | --- |
| `dot > 0` | 目标在**前方**（夹角 < 90°，cos 为正） |
| `dot < 0` | 目标在**后方**（夹角 > 90°，cos 为负） |
| `dot ≈ 0` | 目标在**正侧面**（垂直） |

**② 判断左右——两种等价方法**

- **方法一：点乘 right 向量**（最直观）

```
dot = Vector3.Dot(self.right, dir)
```

`dot > 0` → 目标在**右侧**；`dot < 0` → 目标在**左侧**。

- **方法二：叉乘 forward × dir，看 Y 分量符号**

```
cross = Vector3.Cross(self.forward, dir)   // 结果垂直于 forward 与 dir 所在平面
```

在 Unity **左手坐标系**（forward 为 +Z、Y 朝上）中：`cross.y > 0` → 目标在**右侧**；`cross.y < 0` → 目标在**左侧**；`cross.y ≈ 0` → 正前方/正后方。

**③ 补充说明**

- 原理回顾：点乘只给"夹角大小"信息（前后），叉乘给"旋转方向"信息（左右），两者结合即可在平面内完整定位。
- 若角色朝向可能朝上/朝下（俯仰），判断左右前应把 `dir` 投影到水平面（`dir.y = 0` 后再归一化），否则结果会被俯仰角污染。
- 不必归一化 `dir` 时，点乘符号判断依然成立（因为 |a||b| ≥ 0，符号只由 cosθ 决定），但归一化后数值可作角度/相似度参考。
- 推广：同法可判断"目标是否在视野范围内"（`dot > cos(半视角)`）、"目标是否在攻击距离内"（距离 + 角度）。

## 7.2 矩阵

- **矩阵相乘的意义**：表示线性变换的组合——旋转、缩放、投影、平移、仿射；多个矩阵相乘可以合并为单一变换矩阵。
- **注意点**：
  - 矩阵乘法**不满足交换律**（顺序敏感：先旋转再平移 ≠ 先平移再旋转）；
  - 矩阵的**蠕变**：浮点误差的积累（长期连续变换后矩阵不再正交/缩放漂移）。
- **为什么用 4×4 矩阵而不是 3×3**：4×4 矩阵配合**齐次坐标**可以统一表示平移（3×3 只能表示线性变换，无法表示平移），使各种几何变换（旋转/缩放/平移/投影）统一为矩阵乘法，处理更一致高效。

## 7.3 坐标系与变换（几何体绘制的变换过程）

| 空间 | 说明 |
| --- | --- |
| 模型空间（Local） | 3D 物体的原始坐标，存储在模型中 |
| 世界空间（World） | 物体放入场景后构成的整个游戏场景 |
| 观察空间（View） | 以相机为原点的三维空间 |
| 裁剪空间（Clip） | 判断物体是否在相机渲染范围内（投影 + 裁剪） |
| 屏幕空间（Screen） | 3D 物体投影到屏幕上的 2D 坐标 |

变换链：模型空间 → 世界空间 → 观察空间 → 裁剪空间 → 屏幕空间（M·V·P 矩阵）。

## 7.4 光照

### 7.4.1 光照模型公式

实际光照强度 = 环境光 + 漫反射光 + 镜面高光：

```
I = I_ambient + I_diffuse + I_specular
```

- **环境光**：`I_ambient = A_intensity × A_color`（A_intensity 环境光强度，A_color 环境光颜色）。
- **漫反射**：`I_diffuse = D_intensity × D_color × max(0, N·L)`
  - 即：漫反射光照 = 光源颜色 × 材质漫反射颜色 × max(0, 标准化法线 · 标准化光源方向)。
- **镜面高光**：`I_specular = S_intensity × S_color × (R·V)^n`
  - S 为镜面光强度/颜色，R 为光的反射向量，V 为观察者向量，n 为镜面光指数（光晕系数，越大高光越集中）。

### 7.4.2 其他光照概念

- 点乘在光照中的应用：`max(0, N·L)` 保证背面不产生漫反射。
- 高光公式中的 `(R·V)^n`：视线越接近反射方向高光越强。
- **光照类型**：环境光、漫反射、镜面反射、自发光（Emission）；工程上还要区分**直接光**与**间接光**（全局光照 GI）。

### 7.4.3 Blinn-Phong 与 PBR：照明模型的演进（★★★ 高频）

**从 Phong 到 Blinn-Phong（一个改动，两个收益）**：

| | Phong | **Blinn-Phong** |
| --- | --- | --- |
| 高光项 | `(R·V)^n`，需先算反射向量 `R` | `(N·H)^n`，其中 `H = normalize(L + V)`（半角向量） |
| 计算量 | 每次要算 `reflect(L, N)` | 只多一次向量加法与归一化，**更省** |
| 高光形状 | 大入射角时高光被"拉长"、边缘生硬 | 高光更柔和、更接近真实，**大角度下更稳** |
| 代价 | — | 光源与视线接近平行时半角向量退化，但整体更优 |

- **Unity 的现实**：内置管线的 `Surface Shader` 默认光照模型就是 **Blinn-Phong**（`Lighting.cginc` 的 `BlinnPhong`），所以"Unity 用什么光照模型"默认答 Blinn-Phong。
- **必答的一句**：Blinn-Phong **仍是经验模型**——不遵守能量守恒、没有真实的粗糙度/金属度概念，只适合风格化与性能优先的场景。

**PBR（基于物理的渲染）★★★**：

- **核心思想**：用**物理量**描述材质与光照，保证"同一材质在不同光照环境下表现一致"，而不是靠美术逐场景调参。
- **两大主流工作流**：

| | 金属度-粗糙度（Metallic/Roughness，Unity 标准） | 镜面-光泽度（Specular/Glossiness） |
| --- | --- | --- |
| 贴图 | Albedo / Metallic / Roughness / Normal / AO / Height | Albedo / Specular / Glossiness / Normal |
| 区别 | 用 `Metallic` 一个标量区分金属与非金属，**参数少、不易做出错误材质** | 直接给镜面颜色，**更灵活但容易做出非物理材质** |
| 注意 | **金属没有漫反射**：金属的 Albedo 表示反射色 | 同左 |

- **渲染方程（BRDF 的来历）**：出射辐射 = 所有入射方向贡献的积分 `L_o = ∫ f_r · L_i · (N·L) dω`；实时渲染用**有限光源求和**近似该积分。
- **Cook-Torrance 的三个项（面试常问构成）**：
  1. **D — 法线分布函数（GGX / Trowbridge-Reitz）**：描述微表面朝向分布，决定高光"胖瘦"（粗糙度越高越散）；
  2. **G — 几何遮蔽项（Smith）**：微表面互相遮挡造成的能量损失（掠射角尤其明显）；
  3. **F — 菲涅尔项（Schlick 近似 `F = F0 + (1-F0)(1-cosθ)^5`）**：**掠射角反射率趋近 1**——这就是"为什么水面在远处几乎全反射"的答案。
- **能量守恒与 F0**：反射能量不能超过入射能量（漫反射 + 镜面反射 ≤ 1）；非金属 `F0 ≈ 0.04`（4%），金属的 `F0` 取 Albedo 颜色。
- **IBL（基于图像的光照）**：把环境贴图预计算为**漫反射辐照度图**与**镜面预过滤 mipmap + BRDF LUT**（Unity 里即 Reflection Probe / Lightmap + `UNITY_SPECCUBE_LOD`），用于近似间接光——否则只有直接光的 PBR 会显得很"死"。
- **Unity 里的对应**：**Standard Shader / URP Lit** 都是金属度工作流，HDRP 进一步用物理光单位。若项目是 URP + 2D，则 `Light2D` 走简化的 2D 光照，不涉及上述 BRDF（与 §6.7.2 的管线说明一致）。
- **一句话对比（答题用）**："Blinn-Phong 是**经验模型**，靠参数凑出高光，快但不同光照下不一致；PBR 用**能量守恒 + 微表面 BRDF + 金属度/粗糙度**，材质在任意光照下表现一致，代价是计算更重、需要 IBL 配合。"

## 7.5 渲染管线（图形学视角）

- 3D 渲染管线描述从 3D 模型到最终图像的一系列步骤：
  1. **应用阶段（CPU）**：准备数据（顶点、索引、纹理、材质），做**视锥剔除/遮挡剔除**与排序，输出 DrawCall 与渲染状态；
  2. **几何阶段（GPU）**：顶点着色器做 M·V·P 变换到裁剪空间 → **透视除法（齐次除法）** → 视口变换到屏幕空间；随后**图元装配、背面剔除、裁剪**（并行）；
  3. **光栅化阶段（GPU）**：三角形离散为片元（fragment），属性由 GPU **线性插值**得到；
  4. **像素/片元处理阶段**：片元着色器着色 → **深度测试/模板测试** → **混合** → 写入帧缓冲。
- **细分阶段（现代管线）**：可选加入**曲面细分（Tessellation）**与**几何着色器（Geometry Shader）**，位于顶点与光栅化之间；移动端通常不用（性能与支持度）。
- **可编程 vs 固定管线**：现代管线中顶点/片元着色器可编程；**光栅化、深度测试、混合仍是固定功能**（只能配置，不能编程）。

**Vertex Shader（顶点着色器）**：GPU 上执行的程序，替代固定管线的变换与光照；对输入顶点完成从 local space 到齐次空间（homogeneous space）的变换，包含 world / view / projection 变换（及可选的光照计算）。

**Early-Z 与 Overdraw（★★ 高频优化点）**：

- **Overdraw（过度绘制）**：同一像素被多次着色（透明叠层、全屏特效、大面积 UI 尤其严重）。**它是移动端 GPU 的第一杀手**——因为瓶颈在**填充率/带宽**而非 DrawCall。
- **Early-Z（提前深度测试）**：GPU 在**片元着色之前**先做深度测试，被遮挡的片元直接丢弃、**不执行片元着色器**。这样 Overdraw 的代价只剩深度测试，代价极小。
- **Early-Z 何时失效（面试高频追问）**：
  1. 片元着色器里**写了 `discard`**（Alpha Test）——因为深度可能被改变，GPU 只能退化为 Late-Z；
  2. 片元着色器**修改了深度值**（`SV_Depth` / `ZWrite` 与深度写入配合不当）；
  3. **透明物体**（`ZWrite Off` + 混合）——它们本来就要参与排序后绘制，无法靠 Early-Z 剔除。
- **因此的工程实践**：
  - **不透明物体尽量从近到远绘制**（配合 Early-Z 减少着色量）；
  - **透明物体从远到近**绘制（保证混合结果正确）；
  - 用 **Z-Prepass**（先只写深度、再着色）在不支持 Early-Z 的场景下手动模拟；
  - 用 **Overdraw 视图**（Scene 视图的 Overdraw 模式 / RenderDoc）定位叠层重灾区；
  - 移动端（Tile-Based）尤其要控制**全屏透明特效**与**大面积半透明 UI**。

## 7.6 深度测试 / Alpha 测试 / 模板测试 / ZBuffer

- **深度测试（z-buffer test）**：确定场景中物体前后遮挡关系。每个像素记录深度值，绘制多边形时与帧缓冲当前深度比较，**更靠近观察者的像素被保留**。作用：消除遮挡、提高渲染质量、避免渲染被遮挡像素、提高效率。
- **该测试是否一定开启**：不一定。场景中物体没有遮挡关系、或不关心深度信息时可以不开启（如 UI 顺序绘制、某些特效）。更常见的做法是**保留深度测试但关闭深度写入（`ZWrite Off`）**——透明物体正是如此。
- **可配置的比较函数**：`Less / Greater / LEqual / Always / Never` 等。不透明物体常用 `LEqual`（后画的同深度物体覆盖先画的）；描边、X-Ray、遮挡显示等效果会刻意改成 `Greater`/`Always`。
- **深度是非线性的（Z-Fighting 的根因）**：透视投影后，深度缓冲中的值**与距离不是线性关系**（近处精度极高、远处急剧变差）。因此：
  - **近裁剪面（Near）调得越小，远处精度越差**——`Near` 不应无谓地设成 0.01，通常 0.1~0.3 足够；
  - 距离远的共面物体（贴花、地面、道路标记）容易出现**深度冲突（Z-Fighting）**，表现为闪烁条纹；
  - 缓解手段：拉大 `Near`、用**深度偏移（Polygon Offset）**、把贴花改为**顶点偏移/屏幕空间贴花**、或使用**反转 Z（Reversed-Z）**提升精度分布。
- **A 测**：**Alpha 测试**是基于透明度（alpha 值）的**剔除**技术——alpha 低于阈值的像素直接 `discard`。要点：
  - 它是"全有或全无"，**不参与混合**，因此不透明排序问题较小；
  - **`discard` 会破坏 Early-Z**（§7.5），在移动端（Tile-Based，需保留整块 tile 的深度与颜色直到所有片元处理完）尤其昂贵；
  - 树叶/草丛/栅栏这类"镂空"物体用 Alpha Test 比 Alpha Blend 更省（无排序、可写深度），但边缘会有硬锯齿，通常配合 **Alpha To Coverage（A2C）** 做软边。
- **模板测试（Stencil）**：高级裁剪技术——渲染时把像素与模板缓冲区中的值比较，满足条件才渲染/写入。典型用途：**Mask 裁剪**（UI 圆形头像、技能冷却遮罩）、**轮廓高亮**（先写模板再放大描边）、**阴影体积**、**传送门/镜面**、粒子穿透。它的本质是"给每个像素打标记，后续绘制按标记筛选"。

## 7.7 Alpha 混合方式（公式与应用）

| 方式 | 公式 | 应用 |
| --- | --- | --- |
| 标准 Alpha 混合 | C = 前景透明度 × 前景色 + (1 - 前景透明度) × 背景色（即 `SrcAlpha / OneMinusSrcAlpha`） | 大多数场景：UI 叠加、视频合成 |
| 预乘 Alpha | **先把颜色乘以 alpha 存进贴图**，混合时用 `ONE / OneMinusSrcAlpha`：C = C源 + (1 - α源) × C目标 | 避免半透明边缘出现"黑边/光晕"；渲染引擎处理阴影与半透明物体 |
| 加性混合 | C = C源 + C目标（`ONE / ONE`） | 火焰、闪光、发光效果（**不会变暗，容易过曝**） |
| 乘性混合 | C = C源 × C目标 | 阴影、变暗效果 |
| 屏幕模式混合 | C = 1 - (1 - C源)(1 - C目标) | 高亮、光照溢出效果 |

- 基础公式（经典答法）：实际显示颜色 = 前景颜色 × Alpha/255 + 背景颜色 × (255 - Alpha)/255。
- **"预乘"到底预乘了什么（易错点）**：预乘 Alpha **不是另一套混合方程**，而是**贴图存储时就做 `RGB *= A`**，于是混合式里源因子变成 `ONE`。好处是**纹理过滤/插值时线性**（普通贴图在半透明边缘做双线性过滤会出现"未预乘的 RGB 被平均进来"的黑边），所以粒子、UI 九宫格、带渐隐的贴图都推荐预乘。
- **混合顺序**：透明物体必须**从远到近**绘制（画家算法）才能得到正确结果；这也是为什么透明队列要排序，而**不透明队列可以靠深度测试乱序绘制**（§7.6）。

## 7.8 阴影

### 7.8.1 阴影贴图（Shadow Map）

- 原理：在**光源视角**下预先计算场景可见性，存到阴影贴图纹理中。
- 步骤：① 渲染场景**深度图**；② 进行深度比较；③ 判断阴影状态——若当前像素深度 ≤ 贴图深度，则未被遮挡（在光照中），否则在阴影中。
- 优点：适合动态光源；缺点：有阴影锯齿、自阴影问题。

### 7.8.2 阴影体积（Shadow Volume）

- 原理：创建物体的轮廓边缘并扩展成阴影体积（适合硬阴影/清晰边界）。
- 步骤：① 找到所有可能产生阴影对象的轮廓边缘；② 构建阴影体积；③ 把阴影裁剪为受光照部分；④ 判断场景像素是否位于阴影内。

### 7.8.3 本影与半影 / 自身阴影与投射阴影

- **本影**：没有被光源直接照射的区域（全黑、轮廓分明）。
- **半影**：被部分光源照射的区域（半明半暗）。
- **自身阴影**：物体自身遮挡使某些可见面照不到光；用背面剔除求（假设视点在光源位置）。
- **投射阴影**：不透明物体遮挡光线，使后方物体/区域受不到光；从光源向物体所有可见面投射光线，投影到场景求阴影多边形（空间换时间；动态光源下此方法失效）。

## 7.9 纹理

### 7.9.1 纹理寻址模式

- **Wrapping（重复）**：在每个整数结点对纹理重复。
- **镜像（Mirror）**：纹理在 U/V 方向重复，且每行/每列与相邻行/列成镜像。
- **钳位（Clamp）**：只使用一次纹理，边缘像素颜色被拉伸（抹去）。
- **边界颜色（Border）**：纹理坐标超出范围处使用任意指定的边界颜色。

### 7.9.2 纹理混合方式

- **加权平均**：多个纹理按权重相加得到最终颜色。
- **Alpha 混合**：Alpha 通道值决定纹理颜色在混合中的贡献程度。
- **"纹理插值"这个说法不准确**（术语纠正）：纹理坐标不在整数位置时，按周围纹素取色的正式名称是**纹理过滤（Texture Filtering）**，由 **Filter Mode** 控制，见 §7.9.4。原笔记"纹理插值"混淆了"片元属性插值"（光栅化阶段）与"纹理过滤"（采样阶段）两件事。
- **模式混合**：按叠加、滤色、正片叠底等混合模式决定最终颜色。
- **多纹理混合**：基于光照的混合、基于物理的混合等。

### 7.9.3 阴影贴图的细化：Bias、PCF 与常见瑕疵（★★ 高频追问）

§7.8.1 讲了 Shadow Map 的基本原理（光源视角存深度 → 比较深度判定遮挡）。实际工程里还要处理它带来的三类问题：

**① 自阴影瑕疵（Shadow Acne）与 Bias**：

- **现象**：物体表面出现**条纹状自我遮挡**。
- **原因**：阴影贴图的分辨率有限，一个纹素覆盖了多个表面点，比较时出现"自己挡自己"的精度误差。
- **解法**：加 **深度偏移（Depth Bias / Normal Bias）**——比较时给当前深度加一点偏移。代价是偏移过大时阴影会**脱离物体（peter-panning，影子"飘"起来）**，所以要按场景调小。

**② 锯齿 → PCF（Percentage Closer Filtering）**：

- **现象**：阴影边缘呈锯齿/硬边。
- **解法**：不只比较 1 个纹素，而是比较周围 **N×N 个纹素**并取**遮挡比例**（相当于对"比较结果"做模糊，而不是对深度做模糊）。常见 3×3 / 5×5；也有 **PCSS**（按遮挡物距离动态改变模糊半径，得到"近实远虚"的软阴影）。
- **注意**：PCF 采样数直接决定开销，移动端常用 3×3 或更低。

**③ 其他常见瑕疵与对策**：

| 瑕疵 | 原因 | 对策 |
| --- | --- | --- |
| Peter-panning（影子脱离物体） | Bias 过大 | 减小 Bias、改用 Normal Bias、提高阴影贴图分辨率 |
| 阴影边缘硬/块状 | 分辨率不足 | 提高贴图分辨率、级联阴影（Cascaded Shadow Maps，近处高精度、远处低精度） |
| 大场景阴影精度不够 | 单一阴影贴图覆盖范围过大 | **CSM**（按距离分几级，每级一张贴图）、只对近处物体投影 |
| 半透明物体/Alpha Test 物体阴影不对 | 阴影 Pass 未处理镂空 | 在阴影 Pass 里同样做 `clip(alpha - cutoff)`，或用 A2C |
| 动态物体无阴影 | 只烘焙了静态阴影 | 混合方案：静态物体用 Lightmap 烘焙阴影 + 动态物体用 Realtime Shadow |

- **一句话答题**："Shadow Map 的问题主要是**精度**与**走样**：精度不足会自遮挡（靠 Bias 解决，但 Bias 过大会 peter-panning），走样靠 **PCF** 软化边缘，大场景再叠 **CSM** 分级。"

### 7.9.4 纹理过滤模式与各向异性过滤（★★ 常考，原笔记缺失）

**Filter Mode（采样方式）**：

| 模式 | 做法 | 效果/代价 |
| --- | --- | --- |
| **Point（Nearest）** | 取最近的一个纹素 | 像素风、无模糊；放大时明显马赛克、缩小时严重闪烁 |
| **Bilinear** | 取周围 2×2 纹素做**双线性**加权 | 平滑；缩小时仍会因采样不足而闪烁（需 MipMap） |
| **Trilinear** | 在 Bilinear 基础上，在**相邻两级 MipMap 之间再做一次插值** | 消除 Mip 层级切换时的"跳变"；代价是多采样一级 |

- **MipMap 与 Filter 必须配合理解**：MipMap 解决"缩小采样不足（走样）"，Trilinear 解决"层级切换跳变"，两者一起用才能得到稳定的远景纹理（§7.9.5）。
- **Wrap Mode（寻址模式，§7.9.1）与 Filter 是两件事**：寻址决定"超出 0~1 的 UV 怎么办"，过滤决定"落在纹素之间怎么取色"。

**各向异性过滤（Anisotropic Filtering，AF）**：

- **要解决的问题**：当表面**倾斜**时（如地面、道路向前延伸），屏幕像素在纹理上覆盖的区域是**细长的椭圆**而非正方形；只做各向同性过滤会**过度模糊远处**（因为强行用同一级 Mip）。各向异性过滤按方向**多次采样**来逼近这个椭圆。
- **档位**：1×（关闭）、2×、4×、8×、16×——档位越高，倾斜方向越清晰，**代价是多采样（吃带宽）**。
- **实践建议**：地面/道路/倾斜墙面用 **4×~8×**；UI 与正对相机的贴图**不需要**开（纯浪费带宽）；移动端要克制使用（带宽敏感）。
- **相关设置**：`Texture.importer` 里的 Filter Mode / Aniso Level；Unity 的 **Quality Settings → Anisotropic Textures** 可全局控制（Per Texture / Force Enable / Disable）。

### 7.9.5 MipMap 与纹理压缩

- 见 Unity 章节 §6.7.10（MipMap）、§6.7.9（纹理压缩）。
- **为什么会闪烁（走样）**：屏幕像素在纹理上覆盖的区域远大于一个纹素时，若只取一个采样点，就会"随机"命中不同纹素 → 远景闪烁。**MipMap 用"预生成的低分辨率层级"让采样区域与纹素尺度匹配**，从根源上抑制走样（代价是 +33% 内存与远景变糊）。
- **Mip 与纹理压缩的关系**：压缩纹理（ASTC/ETC2）通常**支持 Mip 链整体压缩**；但 **Mip 层级不能被"手动拼接"**——图集（Atlas）里的每张小图若各自生成 Mip，边缘会互相渗色，所以 UI 图集常关闭 MipMap 或做"图集内 padding + 限制 Mip 级数"。

### 7.9.6 抗锯齿（Anti-Aliasing）（★★★ 高频，原笔记缺失）

**锯齿的成因**：光栅化是**点采样**——一个像素只取一个样本（在该像素中心），几何边缘的覆盖比例被"四舍五入"，于是出现阶梯状边缘（走样）。抗锯齿的本质就是**用更多样本或后处理来估计覆盖比例**。

| 方案 | 原理 | 阶段 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **SSAA**（超采样） | 以更高分辨率渲染再缩小 | 几何+着色 | 质量最好、能处理**着色走样** | 开销按分辨率平方增长，基本不用 |
| **MSAA**（多重采样） | 每个像素用 N 个子样本记录**几何覆盖**，但**只着色一次**，最后按覆盖率混合 | 几何阶段 | 边缘干净、成本远低于 SSAA；**着色只做一次** | **不能解决着色器内部的走样**（高光/纹理闪烁，那要靠 Mip/各向异性）；**与延迟渲染不兼容**（§6.7.2） |
| **FXAA**（快速近似） | 后处理：检测屏幕上的高对比边缘并**模糊** | 后处理 | 极便宜、与管线无关、和延迟渲染兼容 | 会**糊掉细节**（文字/细线变糊），不区分"真边缘" |
| **SMAA** | 后处理改进版（边缘检测 + 形态学权重） | 后处理 | 比 FXAA 清晰、伪影更少 | 比 FXAA 略贵 |
| **TAA**（时间抗锯齿） | 利用**帧间抖动**（每帧亚像素偏移）累积多帧样本；配合运动向量做重投影 | 后处理（跨帧） | 用很少的每帧成本得到接近 SSAA 的稳定性，**同时抑制高光/着色走样**，现代 3A 标配 | 快速运动会出现**拖影/残影（ghosting）**，需要运动向量与历史帧校正，静止场景可能有轻微模糊 |
| **DLSS / FSR** | AI 或算法超分（低分辨率渲染 + 时序重建到高分辨率） | 后处理（跨帧） | 同时起到**抗锯齿 + 提帧**作用 | 依赖硬件/时序稳定性，同样有拖影问题 |

- **选择口径（答题用）**：
  - **移动端 + 前向（URP）**：优先 **MSAA 2×/4×**（便宜、边缘干净），必要时叠加 FXAA；
  - **PC/主机 + 延迟渲染**：MSAA 不可用（G-Buffer 已丢几何信息），用 **TAA / SMAA**；
  - **UI/文字**：避免 FXAA（会糊字），靠**足够分辨率 + 正确的 Filter/Mip 设置**；
  - **性能紧张**：FXAA 是最便宜的兜底。
- **"抗锯齿能不能解决高光闪烁"**：**MSAA 不能**（它只处理几何边缘），**TAA 能**（跨帧累积）。这是区分"懂 MSAA"与"懂抗锯齿"的关键一问。

### 7.9.7 法线变换与切线空间（★★ 中高频，原笔记缺失）

**为什么法线不能直接用模型矩阵变换**：法线是**垂直于表面的方向**，不是位置。若模型矩阵含**非等比缩放**（如 `scale = (1, 2, 1)`），直接用 `M` 变换法线会让它**不再垂直于变换后的表面**——光照全错（表现为缩放后明暗异常）。

**正确做法**：

- 用**法线矩阵**：`N' = normalize( (M⁻¹)ᵀ · N )`
  - 数学推导一句话：要保证"法线与切线点积为 0"在变换后依然成立，就必须用逆转置；
  - **实现上不必求逆**：对只含旋转+等比缩放+平移的矩阵，`(M⁻¹)ᵀ` 与 `M` 的旋转部分成正比（差一个统一缩放因子，归一化即可消除），所以顶点着色器里常写成 `mul((float3x3)unity_WorldToObject, normal)` 再 `normalize`——**用世界到物体的矩阵反而正确**。
  - **Unity 的写法**：`UnityObjectToWorldNormal(v.normal)`（内置换算，等价于上面）；切线用 `UnityObjectToWorldDir(v.tangent.xyz)`。
- **要不要在顶点着色器里归一化**：**必须**。插值会改变向量长度，若把归一化留到片元着色器会得到错误结果（经典 bug：光照在三角形内部变暗）。

**切线空间（Tangent Space）与法线贴图**：

- **法线贴图存的是切线空间下的法线**，取值通常在 `[0,1]`（编码自 `[-1,1]`），基色偏淡蓝紫（对应 `(0,0,1)`，即"不扰动"）。
- **切线空间的三根轴**：`T`（切线，沿 U 方向）、`B`（副切线/副法线，沿 V 方向）、`N`（法线）。三者构成 TBN 矩阵，把贴图里的法线变换到世界/视图空间。
- **`B` 怎么来**：`B = cross(N, T) * T.w`——**乘 `T.w` 是关键**，它携带"UV 是否镜像"的信息，否则镜像 UV 的模型法线会反向（浮雕变凹坑）。
- **为什么用切线空间而不是模型/世界空间法线贴图**：
  1. **可复用**：同一张法线贴图能贴到不同朝向的面上（砖墙的四个面共用一张）；
  2. **可叠加动画**：模型变形（蒙皮）时切线空间法线仍有效；
  3. **压缩友好**：`z` 分量可由 `x,y` 推出（`z = sqrt(1 - x² - y²)`），常见做法是只存两通道（BC5 / 两通道压缩），省 1/3 内存。
- **常见坑**：
  - 忘记归一化插值后的法线 → 光照发灰/发暗；
  - 忘记乘 `T.w` → 镜像 UV 区域明暗反转；
  - 模型**没有切线**（导入设置未计算）→ 法线贴图效果错乱，需在模型导入设置勾选 **Calculate Tangents**；
  - 非等比缩放下未用 `UnityObjectToWorldNormal` → 光照错位。

## 7.10 本章速记

- **光照模型演进**：Lambert（漫反射）→ Phong（加高光，需 `R·V`）→ **Blinn-Phong（改用 `N·H`，更省更稳）**→ **PBR（能量守恒 + 微表面 D/G/F，金属度-粗糙度工作流）**；
- **PBR 三件套**：D 法线分布（GGX）、G 几何遮蔽（Smith）、F 菲涅尔（Schlick）；`F0` 非金属 ≈ 0.04；
- **管线四阶段**：应用 → 几何（顶点/M·V·P/透视除法）→ 光栅化 → 像素处理（着色/深度模板/混合）；
- **Early-Z**：着色前先测深度以省掉被遮挡像素的着色；**`discard`、改深度、透明物体会让它失效**；
- **Overdraw 是移动端第一杀手**（填充率/带宽瓶颈），而非 DrawCall；
- **深度非线性** → `Near` 不宜过小，否则远处 Z-Fighting；
- **Alpha Test 是"全有或全无"、会破坏 Early-Z**；透明必须**从远到近**画；
- **预乘 Alpha 不是另一套公式**，而是"贴图里先 `RGB *= A`"+ 源因子取 `ONE`，为的是过滤时不出现黑边；
- **Filter Mode**：Point / Bilinear / Trilinear（配 Mip 才稳定）；**各向异性过滤解决倾斜表面的模糊**；
- **抗锯齿**：MSAA 只治几何边缘（且不能用于延迟渲染），FXAA 便宜但糊，**TAA 能治高光闪烁但有拖影**；
- **法线变换用逆转置**（Unity 里 `UnityObjectToWorldNormal`），插值后必须归一化；切线空间 `B = cross(N,T) * T.w`，**`T.w` 不能丢**；
- **坐标系**：Unity 是**左手坐标系**，`Vector3.Cross` 遵循左手定则（§7.1.2）。
