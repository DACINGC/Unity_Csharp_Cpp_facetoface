# 九、设计模式与架构

## 9.1 观察者模式

- **定义**：定义对象间一对多的依赖关系，当被观察者状态变化时，自动通知所有观察者。
- **优点**：松耦合；可扩展；符合开闭原则；实时更新；简化对象关系。
- **缺点**：性能问题（频繁通知）；内存泄漏风险（观察者未正确注销）；更新顺序不可控；调试困难；可能被过度使用。
- **适用场景**：事件驱动系统、数据同步、发布-订阅系统、游戏事件系统（UI 监听玩家状态等）。

## 9.2 MVC（Model-View-Controller）

- **Model（模型/数据）**：数据与业务逻辑。
- **View（视图）**：UI 的显示。
- **Controller（控制器）**：监听所有事件、控制逻辑流转；控制器可以拿到视图做出 UI 操作改变，视图控制 UI 的改变。
- 常见做法：每个页面一个控制器；所有事件由控制器监听；视图负责 UI 表现。

## 9.3 单例、工厂、代理、适配器

- **单例（Singleton）**：保证一个类全局只有一个实例，提供全局访问点；注意线程安全与生命周期管理。
- **工厂（Factory）**：把对象创建逻辑与使用逻辑解耦（简单工厂 / 工厂方法 / 抽象工厂），便于扩展新类型。
- **代理（Proxy）**：为对象提供替身/包装以控制访问（延迟加载、权限控制、日志）。
- **适配器（Adapter）**：把一个类的接口转换成客户端期望的另一个接口，解决接口不兼容。

## 9.4 行为树（Behavior Tree）与有限状态机（FSM）

| 对比项 | 行为树 | 有限状态机（FSM） |
| --- | --- | --- |
| 结构 | 树形结构，组合节点（序列/选择）、装饰节点、条件节点、行为节点 | 状态 + 事件驱动转换（如行走、攻击、死亡；玩家靠近、血量不足） |
| 执行 | 自顶向下遍历，根据节点返回状态（成功/失败/运行中）动态选择执行路径 | 每个状态独立定义行为，状态转换由事件和条件触发 |
| 优点 | 模块化、分层、可复用、易于扩展和调试 | 简单直观、实现容易 |
| 缺点 | 实现复杂、性能开销略大 | 状态多时难以维护、扩展性差 |
| 适用 | 复杂 AI（NPC 决策） | 简单明确的有限状态（角色状态） |
