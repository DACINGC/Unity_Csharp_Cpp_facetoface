# 四、操作系统与计算机基础

## 4.1 进程、线程、协程

### 4.1.1 概念对比

| 对比项 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 定义 | 操作系统**资源分配**的基本单位；程序运行后形成的独立内存体 | 进程内的执行单元，操作系统**调度**的最小单位 | 用户态的轻量级"线程"，由程序控制调度 |
| 资源 | 独立的内存空间、地址空间、堆 | 共享进程内存；拥有独立栈、共享堆 | 单线程内并发（交替执行），共享状态无需加锁 |
| 调度 | 操作系统 | 操作系统 | 程序自身（协作式） |
| 开销 | 创建/切换/销毁开销大 | 比进程小 | 极小 |
| 通信 | IPC（管道、消息队列、共享内存等） | 直接共享内存，需同步（锁） | 共享宿主线程上下文 |
| 隔离 | 进程间相互隔离，一个崩溃不影响其他 | 一个线程崩溃可能影响进程 | — |
| 切换方式 | 抢占式 | 抢占式 | 主动让出（yield） |

### 4.1.2 详细说明

**三个核心概念（区别）**：

- **串行**：任务排队执行、互不重叠，前一个完全结束才开始下一个。
- **并发**：任务交错推进、宏观同时进行，单核即可实现；进程间、线程间均为并发（单核时间片交替、多核并行），绝非串行。
- **并行**：同一时刻真正同时执行，需多核。

**进程 / 线程 / 协程**：

- **进程**：程序运行实例（≈ 一个应用程序），OS 以进程为单位分配资源（CPU 时间片、内存）；进程间相互隔离。
- **线程**：进程内的执行单元，不能独立存在；一个进程含多线程；拥有独立栈、共享进程内存，执行不同任务，需同步（锁）。
- **协程**：用户态轻量执行流，程序显式调度（yield/await 挂起恢复），同一线程内交替执行 = 协作式并发（非并行，任一时刻仅一个在执行）；共享堆、各自独立栈；单线程内共享状态无需加锁；Unity 中运行在主线程。

### 4.1.3 进程控制块（PCB）

PCB 是操作系统内核存储进程状态及相关信息的数据结构，包含：

- 进程标识符（进程 ID、父进程 ID 等）；
- 进程状态（运行中、就绪、阻塞等）；
- 处理机状态（寄存器内容、程序计数器、状态寄存器等）。

## 4.2 线程同步

- **锁（Lock/Mutex）**：互斥访问临界区，保证同一时刻只有一个线程进入。
- **信号量（Semaphore）**：控制同时访问资源的线程数量（计数信号量可 >1）。
- **互斥与同步**：互斥解决"竞争"（数据竞争），同步解决"协作"（执行顺序）。
- **条件变量/事件**：线程间通知机制。
- **无锁队列**：基于 **CAS（Compare And Swap）** 等原子操作实现，避免锁竞争，适用于高频读写场景（如游戏网络消息队列）。

## 4.3 内存管理

- **栈（Stack）**：函数调用相关，局部变量/参数/返回地址，自动分配释放，空间小但快。
- **堆（Heap）**：动态申请（new/malloc），需手动释放，空间大但慢，易产生碎片和泄漏。
- **静态区**：全局变量、静态变量。
- **堆栈溢出原因**：递归过深、局部变量过大、栈上分配过多。
- **内存分配方式**：静态分配（编译期确定）、栈上自动分配、堆上动态分配。

## 4.4 编译与运行

- **动态库 vs 静态库**：
  - 静态库（.a/.lib）：链接时复制进可执行文件——发布简单、体积大、更新需重新编译。
  - 动态库（.so/.dll）：运行时加载共享——节省内存、可独立更新、部署需带库文件。
- **编译原理（了解项）**：词法分析 → 语法分析 → 语义分析 → 中间代码生成 → 优化 → 目标代码生成。
- **Debug / Release**：见 C++ 章节 §2.7.6。
- **C 与 C++ 互调**：用 `extern "C"` 正确声明、编译链接（见 §2.3.3）。
