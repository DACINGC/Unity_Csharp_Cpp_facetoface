# 三、数据结构与算法

## 3.1 线性结构

### 3.1.1 链表与数组的区别

| 对比项 | 数组 | 链表 |
| --- | --- | --- |
| 存储 | 连续内存 | 节点分散，通过指针连接 |
| 访问 | 随机访问 O(1) | 需遍历 O(n) |
| 插入/删除 | 移动元素 O(n) | 已知节点时 O(1) |
| 空间 | 可能浪费（预分配） | 每个节点额外存指针 |
| 适用 | 读多写少、按下标访问 | 频繁插入删除、长度不确定 |

### 3.1.2 单链表反转

```csharp
public class ListNode {
    public int val;
    public ListNode next;
    public ListNode(int v) { val = v; }
}

public ListNode ReverseList(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode next = cur.next;   // 先保存后继，防止断链
        cur.next = prev;            // 反转指针方向
        prev = cur;                 // prev 前移
        cur = next;                 // cur 前移
    }
    return prev;                    // 新链头
}
```

### 3.1.3 队列与栈的异同

- 栈：LIFO（后进先出），只在一端操作，适合 DFS、撤销、括号匹配。
- 队列：FIFO（先进先出），一端入一端出，适合 BFS、任务调度。

### 3.1.4 用两个栈实现一个队列

- 入队：压入 `stackIn`。
- 出队：若 `stackOut` 为空，把 `stackIn` 全部弹出并压入 `stackOut`，再从 `stackOut` 弹出（栈颠倒两次即得 FIFO）。

## 3.2 排序算法

### 3.2.1 时间复杂度总表（十大排序）

| 排序 | 平均 | 最坏 | 最好 | 空间 | 稳定性 |
| --- | --- | --- | --- | --- | --- |
| 冒泡 | O(n²) | O(n²) | O(n) | O(1) | 稳定 |
| 选择 | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 |
| 插入 | O(n²) | O(n²) | O(n) | O(1) | 稳定 |
| 希尔 | O(n^1.3) | O(n²) | O(n) | O(1) | 不稳定 |
| 归并 | O(n log n) | O(n log n) | O(n log n) | O(n) | 稳定 |
| 快速 | O(n log n) | O(n²) | O(n log n) | O(log n) | 不稳定 |
| 堆 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳定 |
| 计数 | O(n+k) | O(n+k) | O(n+k) | O(n+k) | 稳定 |
| 桶 | O(n+k) | O(n²) | O(n) | O(n+k) | 稳定 |
| 基数 | O(d·(n+k)) | O(d·(n+k)) | O(d·(n+k)) | O(n+k) | 稳定 |

**各排序要点**（对应上表十种）：

- **冒泡**：相邻两两比较交换，每轮把最大（小）值冒到末尾。
- **直接插入**：把新元素插入到已排好序的前缀中（类似整理扑克牌）。
- **直接选择**：每轮选剩余最小（大）值与当前位置交换。
- **希尔**：插入排序的改进——按步长分组做插入排序，逐步缩小步长到 1；复杂度随步长序列变化（平均 O(n^1.3)、最坏 O(n²)）。
- **归并**：分治，两两合并有序段，稳定但需 O(n) 额外空间。
- **快速**：选基准值分区，递归排序左右两侧；平均 O(n log n)，最坏 O(n²)（实现见 §3.2.2）。
- **堆排序**：利用大/小顶堆，堆顶与末尾交换后调整，O(n log n)。
- **计数**：统计值域内各值出现次数后按序输出；要求可控值域的整数，k 为值域大小，空间 O(n+k)。
- **桶**：按值域分桶，桶内再排序后合并；要求数据近似均匀分布，最坏 O(n²)（全部落入同一桶时退化为桶内排序）。
- **基数**：按位（个位、十位…）分配收集，d 为位数，适合整数/定长字符串。

**补充说明**：

- 十大排序分为**比较排序**（前 7 种）与**非比较排序**（计数/桶/基数，后 3 种，均依赖数据特征）。
- 稳定性记忆口诀：**稳定** = 冒泡、插入、归并、计数、桶、基数；**不稳定** = 选择、希尔、快速、堆。

### 3.2.2 快速排序（C# 实现，来自笔记）

```csharp
// 分区函数：返回基准值最终位置
static int Partition(int[] arr, int low, int high) {
    int l = low, r = high, pivot = arr[low];
    while (l < r) {
        while (l < r && arr[r] > pivot) r--;
        if (l < r) { (arr[l], arr[r]) = (arr[r], arr[l]); l++; }
        while (l < r && arr[l] < pivot) l++;
        if (l < r) { (arr[l], arr[r]) = (arr[r], arr[l]); r--; }
    }
    return l;
}

// 快速排序函数
static void QuickSort(int[] arr, int low, int high) {
    if (low < high) {
        int pi = Partition(arr, low, high);
        QuickSort(arr, low, pi - 1);
        QuickSort(arr, pi + 1, high);
    }
}
```

## 3.3 查找

### 3.3.1 二分查找

```csharp
static int BinarySearch(int[] arr, int n, int target) {
    int l = 0, r = n - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;   // 防溢出
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) l = mid + 1;
        else r = mid - 1;
    }
    return -1; // 未找到
}
// 也可直接用：Array.BinarySearch(arr, target)（未找到返回负数）
```

### 3.3.2 二叉排序树 / 平衡树 / 红黑树 / B 树

| 结构 | 规则要点 | 查找复杂度 |
| --- | --- | --- |
| 二叉排序树（BST） | 左节点 < 根 < 右节点 | 平均 O(log n)，退化为链表时 O(n) |
| 平衡二叉树（AVL） | 满足 BST；任意节点左右子树高度差不超过 1；插入删除后可能破坏平衡，需找最小不平衡子树调整，开销大 | O(log n) |
| 红黑树（RBT） | 满足 BST；插入删除很少破坏规则，调整是常数级时间 | O(log n) |
| B 树（m 阶多路平衡查找树） | 除根节点外，任何节点至少有 ⌈m/2⌉ 个分叉；任一节点所有子树高度相同 | O(log n)，适合磁盘/数据库 |
| B+ 树（m 阶） | 非根叶子节点至少 ⌈m/2⌉ 棵子树；所有数据在叶子节点，叶子间有序链表 | O(log n)，数据库索引常用 |

**各自定义：**

- **二叉排序树（BST）**：二叉树，满足左子树所有节点 < 根节点 < 右子树所有节点，左右子树各自也是 BST；中序遍历得到递增有序序列。
- **平衡二叉树（AVL）**：在 BST 基础上，任意节点的左右子树高度差（平衡因子）绝对值不超过 1；插入/删除后失衡时通过旋转（LL/RR/LR/RL）恢复平衡，是严格平衡的二叉查找树。
- **红黑树（RBT）**：在 BST 基础上节点带红/黑颜色，满足 5 条性质：节点非红即黑；根为黑；叶子（NIL）为黑；红节点的两个子节点都是黑（红节点不能连续）；任一节点到其每个叶子的路径包含相同数目的黑节点。最远路径不超过最近路径的 2 倍，属近似平衡，插入/删除后通过变色 + 旋转调整。C# 的 `SortedDictionary`/`SortedSet` 底层就是红黑树。
- **B 树（m 阶多路平衡查找树）**：多路平衡查找树，每个节点可存多个关键字和多棵子树，所有叶子在同一层（树高一致）；除根节点外每个节点至少有 ⌈m/2⌉ 棵子树。多路结构降低树高、减少磁盘 IO，适合磁盘/数据库存储。
- **B+ 树**：B 树的变体，所有数据都存放在叶子节点，内部节点只存索引关键字，因此能容纳更多索引项、树更矮；叶子节点间用指针构成有序链表，便于范围查询和顺序遍历，数据库索引（如 MySQL InnoDB）常用。

## 3.4 哈希表

### 3.4.1 哈希表原理、冲突解决与适用环境

**原理**：

- 通过**哈希函数**把键映射为数组下标（`哈希码 → 桶索引`），键值对存于对应桶中；理想情况下 **O(1) 定位**（平均 O(1)，最坏 O(n)）。
- 好的哈希函数要求：**计算快、分布均匀**（避免聚集）；`Equals` 相等的键必须产生相同的哈希码（相等契约，与 §1.3.2 一致）。

**冲突解决**：

| 方法 | 思路 | 特点 |
| --- | --- | --- |
| 链地址法 | 桶内挂链表（元素多时可转红黑树，如 Java HashMap） | 删除简单、容忍较高负载因子；C# `Dictionary`、Java `HashMap` 采用 |
| 线性探测 | 冲突后向后依次找下一个空位（+1、+2…） | 数据连续、缓存友好；删除需标记（墓碑），负载过高易聚集 |
| 二次探测 | 按 +1²、+2²、+3²… 找空位 | 缓解线性聚集 |
| 再哈希（双重哈希） | 用第二个哈希函数计算探测步长 | 分布更均匀，实现稍复杂 |

**扩容（rehash）**：

- 负载因子 = 已存元素数 / 桶数；超过阈值（各实现不同）时**扩容并重新哈希**所有键，O(n)——这是哈希表"偶尔插入变慢"的原因。
- C# `Dictionary` 扩容到下一个**质数**，可减少取模分布的聚集。

**复杂度**：查找/插入/删除**平均 O(1)**、**最坏 O(n)**（所有键冲突到同一桶）；哈希分布越均匀越接近 O(1)。

**适用与不适用**：

- 适用：查重、按键快速取值（`Dictionary`/`HashSet`/缓存/计数统计）。
- 不适用：**有序遍历、范围查询、前缀查询**——哈希表无序，此类需求应选树（`SortedDictionary`/B+ 树）或跳表。

- C# `Dictionary` 底层（桶 + 条目、链地址、扩容到质数）详见 §1.3.2。

## 3.5 树与图

### 3.5.1 树与图的遍历：BFS 与 DFS

| 对比项 | BFS（广度优先） | DFS（深度优先） |
| --- | --- | --- |
| 遍历方式 | 逐层遍历，先访问根再访问所有相邻节点 | 沿一条路径深入到底，再回溯探索其他路径 |
| 数据结构 | 队列（FIFO） | 栈（LIFO）；递归实现用系统调用栈 |
| 空间复杂度 | 最坏 O(n)（如完全二叉树），n 为节点数 | 取决于深度，最坏 O(h)，h 为最大深度 |
| 适用场景 | 最短路径、层次遍历 | 拓扑排序、连通性检测、路径搜索 |

### 3.5.2 拓扑排序与逆拓扑排序

- **拓扑排序**：找到**入度为 0** 的点开始构建（做事有先后顺序的场景，如依赖任务）。
- **逆拓扑排序**：找到**出度为 0** 的点开始构建。

### 3.5.3 最小生成树

- **定义**：带权无向**连通图**中，选出 n-1 条边把所有顶点连通、且**总权值和最小**的生成树。对该问题，局部贪心即可得到全局最优（贪心选择性质）。

| 对比项 | Prim 算法 | Kruskal 算法 |
| --- | --- | --- |
| 策略 | 找**顶点** | 找**边** |
| 核心思想 | 从任一顶点出发，维护已选集合 U 与未选集合，每次选连接两集合的**最小权边**，把该顶点并入 U，直到全部顶点并入 | 所有边**按权值从小到大**排序，依次取边，用**并查集**判断两端点是否已连通（成环则跳过），直到选够 n-1 条边 |
| 关键数据结构 | 已选集合 + 优先队列（取最小边） | 边排序 + 并查集（判环） |
| 时间复杂度 | 邻接矩阵 O(V²)；优先队列优化 O(E log V) | O(E log E)（主要开销在排序） |
| 适合场景 | 稠密图 | 稀疏图 |

- 都只适用于带权**无向连通图**；生成树边数恒为 n-1（n 为顶点数）。
- 典型应用：修路、网络布线——使所有节点连通且总成本最小。

### 3.5.4 最短路径

- **松弛（Relaxation）**：三者共同基础——若 `dist[v] > dist[u] + w(u,v)`，则更新 `dist[v]`（经 u 到 v 更短）。

| 对比项 | Dijkstra | Bellman-Ford | Floyd |
| --- | --- | --- | --- |
| 类型 | 单源（一个起点到所有点） | 单源 | 多源（任意两点之间） |
| 核心思想 | 贪心：每次从未确定的点中取 dist 最小的点（优先队列），松弛其出边，点一旦确定不再改变 | 对全部边做 **n-1 轮**松弛（最短路径最多含 n-1 条边）；**第 n 轮仍能松弛 → 存在负环** | 动态规划：`dp[i][j] = min(dp[i][j], dp[i][k]+dp[k][j])`，k 为中间点（可滚动为二维） |
| 边权要求 | **不能有负权边**（负权使贪心失效） | 可处理负权边 | 可处理负权边，但不能有负环 |
| 负环检测 | 不能 | 能 | 能（对角线 `dp[i][i] < 0` 即存在） |
| 时间复杂度 | O((V+E) log V)（堆优化） | O(V·E) | O(n³)，空间 O(n²) |
| 适用场景 | 非负权图单源最短路（最常用） | 有负权边、需检测负环 | 顶点少、求所有点对最短路 |

## 3.6 寻路算法：A*（A Star）

### 3.6.1 原理与核心流程

**定义**：A*（A-Star）是**启发式最短路径算法**——在 Dijkstra 的实际移动代价基础上，加入对目标距离的估算，从而优先搜索更可能到达终点的节点。

**核心公式**：

```text
F(n) = G(n) + H(n)
```

- `G(n)`：起点到当前节点的**实际代价**。
- `H(n)`：当前节点到终点的**预估代价**。
- `F(n)`：经过当前节点到达终点的**预计总代价**；每次取 F 最小的节点扩展。

**两个集合**：

- **Open Set**：已发现、尚未检查的节点（按 F 排序）。
- **Closed Set**：已处理过的节点。

**执行步骤**：

```text
1. 起点加入 Open Set（G=0，计算 H、F）
2. 取出 F 最小的节点 current；是终点 → 回溯路径
3. current 移入 Closed Set
4. 遍历 current 的相邻节点：
   - 跳过障碍物与 Closed Set 中的节点
   - 计算经 current 到邻居的新 G；更短则更新 G、H、F 与父节点
   - 未发现的邻居加入 Open Set
5. 重复，直到找到终点或 Open Set 为空（无路径）
```

**路径重建**：从终点沿父节点回溯到起点，反转即最短路径——所以每个节点必须记录父节点。

**启发函数对结果的影响**：

| 情况 | 效果 |
| --- | --- |
| `H = 0` | 退化为 Dijkstra，保证最短路径但搜索范围大 |
| `H` 合理 | 保证最短路径，并减少搜索节点 |
| `H` 过大 | 搜索更快，但可能无法保证最短路径 |
| 只用 `H` | 接近贪心最佳优先搜索 |

- **保证最优的条件**：`H(n)` 不大于节点 n 到终点的真实最小代价（启发函数不能高估实际剩余代价）。
- 移动代价为正时满足一致性，每个节点只需扩展一次。

### 3.6.2 启发式函数（H 的计算）

| 距离 | 公式 | 适用 |
| --- | --- | --- |
| 曼哈顿距离 | H = \|x1-x2\| + \|y1-y2\| | 四方向移动（上下左右）的网格 |
| 对角距离 | dx = \|x1-x2\|，dy = \|y1-y2\|；H = 14×min(dx,dy) + 10×\|dx-dy\|（直线 10、斜线 14，即 √2 的整数近似） | 八方向移动的网格 |
| 欧几里得距离 | H = √((x1-x2)² + (y1-y2)²) | 任意方向自由移动 |

- 所有节点必须用**同一公式**计算 H；H 只是预估，不依赖障碍布局。
- 切比雪夫距离 `max(|dx|, |dy|)` 是八方向的下限估计，对角距离更精确。

### 3.6.3 C# 网格版核心实现

```csharp
using System;
using System.Collections.Generic;

public sealed class AStarNode
{
    public int X;
    public int Y;
    public bool Walkable = true;

    public int G = int.MaxValue;
    public int H;
    public int F => G + H;

    public AStarNode Parent;
}

public static class AStar
{
    private static readonly (int x, int y, int cost)[] Directions =
    {
        ( 0,  1, 10), ( 0, -1, 10), ( 1,  0, 10), (-1,  0, 10),  // 四方向：代价 10
        ( 1,  1, 14), ( 1, -1, 14), (-1,  1, 14), (-1, -1, 14)   // 斜方向：代价 14
    };

    public static List<AStarNode> FindPath(AStarNode[,] grid, AStarNode start, AStarNode target)
    {
        ResetNodes(grid);

        var openSet = new List<AStarNode>();
        var closedSet = new HashSet<AStarNode>();

        start.G = 0;
        start.H = Heuristic(start, target);
        openSet.Add(start);

        while (openSet.Count > 0)
        {
            AStarNode current = FindLowestCostNode(openSet);
            if (current == target) return BuildPath(target);

            openSet.Remove(current);
            closedSet.Add(current);

            foreach (var d in Directions)
            {
                int x = current.X + d.x, y = current.Y + d.y;
                if (!IsInside(grid, x, y)) continue;

                AStarNode neighbor = grid[x, y];
                if (!neighbor.Walkable || closedSet.Contains(neighbor)) continue;

                // 防止斜向穿过两个障碍物之间的墙角
                if (d.x != 0 && d.y != 0 && !CanMoveDiagonally(grid, current.X, current.Y, d.x, d.y)) continue;

                int newG = current.G + d.cost;
                if (newG >= neighbor.G) continue;

                neighbor.Parent = current;
                neighbor.G = newG;
                neighbor.H = Heuristic(neighbor, target);
                if (!openSet.Contains(neighbor)) openSet.Add(neighbor);
            }
        }
        return null;
    }

    private static int Heuristic(AStarNode node, AStarNode target)
    {
        int dx = Math.Abs(node.X - target.X);
        int dy = Math.Abs(node.Y - target.Y);
        return 14 * Math.Min(dx, dy) + 10 * Math.Abs(dx - dy);   // 对角距离（10/14）
    }

    private static AStarNode FindLowestCostNode(List<AStarNode> openSet)
    {
        AStarNode best = openSet[0];
        for (int i = 1; i < openSet.Count; i++)
            if (openSet[i].F < best.F || (openSet[i].F == best.F && openSet[i].H < best.H))
                best = openSet[i];   // F 相同取 H 小的，路径更优
        return best;
    }

    private static List<AStarNode> BuildPath(AStarNode target)
    {
        var path = new List<AStarNode>();
        for (AStarNode node = target; node != null; node = node.Parent) path.Add(node);
        path.Reverse();
        return path;
    }

    private static bool IsInside(AStarNode[,] grid, int x, int y)
        => x >= 0 && y >= 0 && x < grid.GetLength(0) && y < grid.GetLength(1);

    private static bool CanMoveDiagonally(AStarNode[,] grid, int x, int y, int dx, int dy)
        => grid[x + dx, y].Walkable && grid[x, y + dy].Walkable;

    private static void ResetNodes(AStarNode[,] grid)
    {
        foreach (var node in grid) { node.G = int.MaxValue; node.H = 0; node.Parent = null; }
    }
}
```

> 示例为突出原理，用 `List` 线性查找最小 F 节点（O(n)），性能并非最优；工程上改用最小堆（见 §3.6.4）。

### 3.6.4 性能优化

1. **Open Set 用优先队列/最小堆**：`List` 取最小 F 是 O(n)；最小堆插入与取最小均为 O(log n)（.NET 6+ 可用 `PriorityQueue<TElement, TPriority>`，低版本自实现二叉堆）。
2. **避免每次寻路创建节点**：网格节点提前创建并复用，减少 GC；也可用数组保存 G 值、父节点索引、节点状态。
3. **避免重复清空整个地图**：大图遍历重置代价高，可用**搜索版本号**、只记录本次访问过的节点、寻路数据对象池。
4. **分层或区域寻路**：超大地图用分区寻路、HPA*、导航网格、路径缓存、Flow Field（大量单位前往同一区域）；网格地图可加 JPS（跳跃点搜索）跳过对称路径。
5. **路径平滑**：网格路径呈锯齿状，用射线检测删除可直达的中间节点（A 能直达 C 则删 B）。

### 3.6.5 常见问题与面试话术

**常见问题**：

- 四方向移动用曼哈顿距离，八方向移动用对角距离；允许斜向移动时要**防止穿墙角**（斜向移动要求两侧相邻格子可通行）。
- 地形代价应加入 `G`（如沼泽比道路代价更高）；修改已在优先队列中的节点代价时需更新优先级，或重新入队并在出队时忽略旧记录。
- 动态障碍物变化后原路径可能失效，需局部重算或重新寻路。
- A* 的效果取决于地图表示、启发函数与 Open Set 数据结构。

**面试话术**：

> A* 是结合 Dijkstra 与启发式搜索的最短路径算法，核心评价函数是 `F = G + H`。`G` 是起点到当前节点的实际代价，`H` 是当前节点到终点的预估代价。算法每次从 Open Set 中取 F 最小的节点扩展，处理完放入 Closed Set，并记录每个节点的最优 G 值与父节点；找到终点后沿父节点回溯路径。只要启发函数不高估真实剩余代价，A* 就保证找到最短路径。实际优化重点是：用最小堆管理 Open Set、选对启发函数、复用节点数据、防止斜向穿墙。

## 3.7 其他考点

### 3.7.1 大端与小端

- **小端模式**：数据**低位**放在**低地址**，高位放在高地址（低位对应低地址）。
- **大端模式**：数据**高位**放在**低地址**，低位放在高地址。
- 读数据永远从低地址开始：小端模式从低位开始读，大端模式从高位开始读。

### 3.7.2 进制转换

- 十进制 → 二进制：**除 2 取余，倒序排列**。
- 二进制 → 八进制：**三位一组**（不够前补零），按 421 法将 1 对应的值相加。
- 二进制 → 十六进制：**四位一组**（不够前补零），按 8421 法将 1 对应的值相加。

### 3.8.6 二叉树遍历（先序/中序/后序/层序）

- **先序（前序）**：根 → 左 → 右；**中序**：左 → 根 → 右；**后序**：左 → 右 → 根（中序遍历 BST 得到有序序列）。
- 递归实现（以先序为例）：

```csharp
void Preorder(TreeNode root) {
    if (root == null) return;
    Visit(root);              // 根
    Preorder(root.left);      // 左
    Preorder(root.right);     // 右
}
```

- **层序（BFS）**：用队列，先根入队，出队时访问并依次将左右孩子入队。
- 迭代实现：先/中/后序用**栈**模拟递归（先序：栈压右再压左，出栈即访问）。
- 由遍历序列重建二叉树：先序/后序 + 中序可唯一确定二叉树（前序确定根，中序划分左右子树）。

**C# 实现**：

```csharp
public class TreeNode {
    public int val;
    public TreeNode left, right;
    public TreeNode(int v) { val = v; }
}

// 递归（三种只差访问位置）：先序 根左右 / 中序 左根右 / 后序 左右根
void Pre(TreeNode n, List<int> r)  { if (n == null) return; r.Add(n.val); Pre(n.left, r); Pre(n.right, r); }
void In(TreeNode n, List<int> r)   { if (n == null) return; In(n.left, r); r.Add(n.val); In(n.right, r); }
void Post(TreeNode n, List<int> r) { if (n == null) return; Post(n.left, r); Post(n.right, r); r.Add(n.val); }

// 迭代先序：栈，压右再压左
List<int> PreIter(TreeNode root) {
    var r = new List<int>();
    var s = new Stack<TreeNode>();
    if (root != null) s.Push(root);
    while (s.Count > 0) {
        var n = s.Pop();
        r.Add(n.val);
        if (n.right != null) s.Push(n.right);
        if (n.left != null) s.Push(n.left);
    }
    return r;
}

// 迭代中序：一路向左入栈，出栈访问后转右
List<int> InIter(TreeNode root) {
    var r = new List<int>();
    var s = new Stack<TreeNode>();
    var cur = root;
    while (cur != null || s.Count > 0) {
        while (cur != null) { s.Push(cur); cur = cur.left; }
        cur = s.Pop();
        r.Add(cur.val);
        cur = cur.right;
    }
    return r;
}

// 迭代后序：先序变体得到"根右左"，反转即"左右根"
List<int> PostIter(TreeNode root) {
    var r = new List<int>();
    var s = new Stack<TreeNode>();
    if (root != null) s.Push(root);
    while (s.Count > 0) {
        var n = s.Pop();
        r.Add(n.val);
        if (n.left != null) s.Push(n.left);
        if (n.right != null) s.Push(n.right);
    }
    r.Reverse();
    return r;
}

// 层序（BFS）：队列
List<int> LevelOrder(TreeNode root) {
    var r = new List<int>();
    var q = new Queue<TreeNode>();
    if (root != null) q.Enqueue(root);
    while (q.Count > 0) {
        var n = q.Dequeue();
        r.Add(n.val);
        if (n.left != null) q.Enqueue(n.left);
        if (n.right != null) q.Enqueue(n.right);
    }
    return r;
}
```

### 3.8.7 KMP 字符串匹配

- **问题**：在文本串 S 中查找模式串 P 第一次出现的位置。
- **朴素算法**：逐个位置比对，失败后模式串只后移 1 位，最坏 O(n·m)。
- **KMP 核心**：匹配失败时**不回溯文本指针 i**，而是利用已匹配部分的信息把模式串**右移到合适位置**继续匹配，最坏 O(n+m)。
- **next 数组（部分匹配表/前缀函数）**：`next[j]` 表示 P[0..j-1] 中相等的最长真前后缀长度——即模式串第 j 位失配时，模式串应跳回的位置。

```csharp
// 计算 next 数组（前缀函数）
static int[] GetNext(string p) {
    int m = p.Length;
    int[] next = new int[m];
    int k = 0;
    for (int j = 1; j < m; j++) {
        while (k > 0 && p[j] != p[k]) k = next[k - 1];
        if (p[j] == p[k]) k++;
        next[j] = k;
    }
    return next;
}

// KMP 匹配：返回 P 在 S 中首次出现的下标，不存在返回 -1
static int Kmp(string s, string p) {
    int n = s.Length, m = p.Length;
    if (m == 0) return 0;
    int[] next = GetNext(p);
    int j = 0;                       // 模式串指针，不回溯
    for (int i = 0; i < n; i++) {
        while (j > 0 && s[i] != p[j]) j = next[j - 1];
        if (s[i] == p[j]) j++;
        if (j == m) return i - m + 1;
    }
    return -1;
}
```

- 适用：字符串查找、文本编辑器查找、DNA 序列比对等对性能有要求的场景。

### 3.8.8 洗牌算法（Fisher-Yates / Knuth Shuffle）

**问题**：把数组（或 List）中的元素随机打乱，要求**每种排列以等概率出现**（均匀分布）。

**思路演进**：

- **朴素方法**：每次从剩余元素中随机抽一张放入新数组——需要 O(n) 额外空间和删除操作，实现易错。
- **Fisher-Yates（费雪-耶茨）/ Knuth 洗牌**：从后往前（或从前往后）遍历，每一步在"当前位置及之后"的范围内随机选一个下标交换，**原地完成**，O(n) 时间、O(1) 空间。这是工业标准解法（C# `List` 没有内置，Java `Collections.shuffle` 即为其实现）。

**关键点（易错）**：

- 随机区间必须**包含当前位置 i**：从后往前要写 `rng.Next(i + 1)`（即 [0, i]）；若漏掉 i，会导致分布不均匀（部分元素永远不会留在原位）。
- 每步每个剩余元素被抽中的概率相等，故任意排列概率都是 1/n!（归纳法可证）。
- `Random` 只创建一个实例复用；每次循环 `new Random()` 会因相同种子产生完全相同的序列。
- C# `Random.Next(min, max)` 内部已消除取模偏置（modulo bias），直接用即可。

**C# 实现**：

```csharp
// 数组版（从后往前）：原地、均匀、O(n)
static void Shuffle<T>(T[] arr, Random rng) {
    for (int i = arr.Length - 1; i > 0; i--) {
        int j = rng.Next(i + 1);            // 关键：范围 [0, i]，包含 i
        (arr[i], arr[j]) = (arr[j], arr[i]);
    }
}

// List 版（从前往后）：
static void Shuffle<T>(List<T> list, Random rng) {
    for (int i = 0; i < list.Count - 1; i++) {
        int j = rng.Next(i, list.Count);    // 范围 [i, Count)
        (list[i], list[j]) = (list[j], list[i]);
    }
}
```

**Unity 应用**：

- 抽卡/抽奖、斗地主发牌、题库随机出题、BGM 随机播放（洗一遍后顺序播放，避免纯随机导致频繁重复）。
- Unity 中整数随机可用 `UnityEngine.Random.Range(0, i + 1)`（int 重载为左闭右开），或直接用 `System.Random`。

**不推荐的写法**：

- `list.OrderBy(x => rng.Next())`：基于排序，O(n log n) 且均匀性依赖实现细节，面试中不作为标准答案。
