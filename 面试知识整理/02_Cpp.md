# 二、C++ 语言

## 2.1 内存管理

### 2.1.1 C++ 程序内存分区

| 区域 | 存储内容 | 管理方式 |
| --- | --- | --- |
| 栈区 | 函数调用时的局部变量、函数参数、返回地址 | 编译器自动分配/释放 |
| 堆区 | 动态分配的内存（new / malloc） | 需手动释放 |
| 全局/静态区 | 全局变量、静态变量（分已初始化区、未初始化区） | 程序生命周期内存在 |
| 代码区 | 程序二进制代码（函数体、类方法） | 只读 |

### 2.1.2 内存泄漏与内存碎片

| 问题 | 原因 | 避免方法 |
| --- | --- | --- |
| 内存泄漏 | 未释放内存、指针丢失、异常未处理 | 智能指针、RAII（资源获取即初始化）、异常安全代码 |
| 内存碎片 | 频繁分配/释放、大小不一 | 内存池、对象池、减少动态内存分配 |

### 2.1.3 new 与 malloc 的区别

| 对比项 | new | malloc |
| --- | --- | --- |
| 类型安全 | 自动计算所需内存大小，返回类型化指针 | 手动计算大小，返回 `void*`，需显式转换 |
| 初始化 | 自动调用构造函数 | 仅分配内存，不初始化 |
| 释放 | `delete`，自动调用析构函数 | `free`，不调用析构函数 |
| 失败处理 | 抛出 `std::bad_alloc` 异常 | 返回 NULL |
| 功能扩展 | 支持运算符重载 | 不支持 |
| 适用场景 | C++ 中动态创建对象 | C 风格内存分配或与 C 库兼容场景 |

### 2.1.4 delete 与 delete[] 的区别

- `delete` 释放单个对象，调用该对象的析构函数。
- `delete[]` 释放对象数组，逐个调用每个元素的析构函数。
- 错误混用（new[] 配 delete 或 new 配 delete[]）会导致**未定义行为**（可能内存泄漏或崩溃）。

### 2.1.5 智能指针与 RAII

- **RAII**：资源获取即初始化——用对象生命周期管理资源（内存、文件句柄、锁），析构时自动释放。
- `unique_ptr`：独占所有权，不可拷贝。
- `shared_ptr`：共享所有权，引用计数归零时释放。
- `weak_ptr`：弱引用，不增加引用计数，用于打破循环引用。
- 裸指针 `new`/`delete` 在现代 C++ 中应尽量用智能指针替代。

## 2.2 指针与引用

### 2.2.1 引用与指针的区别

| 对比项 | 引用 | 指针 |
| --- | --- | --- |
| 定义 | 变量的别名，必须初始化 | 存储地址的变量，可稍后赋值 |
| 重新绑定 | 不能重新指向其他对象 | 可以改变指向 |
| 空值 | 不能为 null（必须绑定对象） | 可以为 nullptr |
| 运算 | 无指针运算（++、-- 等） | 支持算术运算 |
| 内存 | 不额外占用（编译器实现为常量指针） | 占用一个指针大小的内存 |
| 安全 | 相对安全 | 易产生野指针、越界 |

### 2.2.2 指针常量与常量指针

- **常量指针（pointer to const）**：`const int *p` / `int const *p`——指向常量的指针，**不能通过 p 修改指向的值**，但 p 可以指向别处。
- **指针常量（const pointer）**：`int *const p`——指针本身是常量，**p 不能再指向别处**，但可以通过 p 修改指向的值。
- 记忆：`const` 修饰谁，谁不可变。`const char *p` 与 `char *const p` 同理。

### 2.2.3 野指针的成因与避免

- **成因**：
  1. 未初始化的指针（指向随机地址）；
  2. 指向已释放的内存（free/delete 后未置空）；
  3. 指针越界（超出数组或动态分配内存范围）；
  4. 返回局部变量的地址（局部变量销毁后指针失效）。
- **避免**：声明时初始化（或置 `nullptr`）、释放后置空、不返回局部对象地址、用智能指针。

### 2.2.4 数组名与指针、a 与 &a 的区别

- 数组名是**首元素地址的常量**（不是变量，不能自增/被赋值），`sizeof(数组名)` 得到整个数组大小。
- 指针是变量，`sizeof(指针)` 得到指针本身大小（如 8 字节 64 位）。
- `int a[5]`：`a` 是首元素地址（`int*`）；`&a` 是整个数组的地址（`int(*)[5]`），两者数值相同但类型不同，`a+1` 跳过一个元素，`&a+1` 跳过整个数组。
- 数组作为函数实参时会**退化为指针**（丢失长度信息）。

### 2.2.5 函数指针与指针函数

- **函数指针**：指向函数的指针，`int (*fp)(int, int)`，用于回调、表驱动。
- **指针函数**：返回值为指针的函数，`int* func()`。

### 2.2.6 如何避免悬垂/越界等指针问题

- 对应经典题"如何避免野指针"：初始化、置空、智能指针、边界检查。

## 2.3 关键字

### 2.3.1 const

- 定义不可修改的常量，或限制对数据的修改权限；声明时必须初始化，类型安全。
- `const` 成员函数：承诺不修改对象状态（`mutable` 成员除外）。
- 常引用（`const T&`）：既能避免拷贝开销，又能保证只读，常用于函数参数。

### 2.3.2 static

| 场景 | 作用 |
| --- | --- |
| 静态局部变量（函数内） | 延长生命周期至程序结束，仅初始化一次，作用域仍限函数内 |
| 静态成员变量（类内） | 属于类本身，所有实例共享同一份数据；必须在类外单独初始化 |
| 静态成员函数（类内） | 无需实例即可调用，无 `this` 指针，只能访问静态成员 |
| 静态全局变量/函数（文件作用域） | 内部链接，仅当前文件可见，避免命名冲突 |

### 2.3.3 extern 与 extern "C"

- `extern`：声明变量/函数具有外部链接性，定义在其他文件或作用域中。注意：`extern` 声明不能初始化（除非 const）；全局变量必须且只能在一个文件中定义。
- `extern "C"`：告诉 C++ 编译器按 **C 语言方式**处理符号（不进行名字修饰/重载），用于在 C++ 中调用 C 函数或让 C 调用 C++ 函数。

```cpp
extern "C" {
    void my_function(int a, int b);
}
```

### 2.3.4 volatile

- 告诉编译器该变量可能被外部（硬件、其他线程、中断）修改，**不要优化掉对它的读写**，每次直接访问内存。
- 可以修饰指针（如指向硬件寄存器的指针）。

### 2.3.5 typedef 与 #define 的区别

- `typedef`：为类型起别名，编译期处理，有类型检查。
- `#define`：文本宏替换，预处理期处理，无类型检查；定义宏时注意**整体加括号**防止优先级问题。

```cpp
#define MIN(a, b) ((a) < (b) ? (a) : (b))   // 标准 MIN 宏
```

### 2.3.6 inline 与虚函数、构造函数

- 内联函数：编译期将函数体展开，减少调用开销；适合短小、频繁调用的函数。
- 虚函数可以声明为 inline，但**实际不会被内联**（虚函数需要动态绑定，与内联的静态展开语义冲突）。
- **构造函数不能是虚函数**：虚函数依赖虚表实现多态，而虚表/虚指针的初始化发生在构造函数执行阶段；构造函数的类型必须在编译时确定。

## 2.4 面向对象

### 2.4.1 面向对象三大特性

- **封装**：将数据和方法捆绑成类，隐藏内部细节，暴露接口。
- **继承**：子类继承父类的属性和方法，通过重写/扩展实现代码复用。
- **多态**：同一操作在不同环境下产生不同行为——编译时多态（重载、模板）、运行时多态（虚函数 + 动态绑定）。

### 2.4.2 class 与 struct 的区别

- 默认访问权限不同：`class` 默认 `private`，`struct` 默认 `public`。
- C++ 中两者都可以有成员函数、继承（区别于 C 的 struct）。

### 2.4.3 空类的大小与默认成员函数

- 空类 `sizeof(A)` 为 **1**（编译器给一个占位字节，保证不同对象有唯一地址，不能为 0）。
- 编译器自动生成的四个默认函数：**默认构造函数、析构函数、拷贝构造函数、赋值运算符**。

### 2.4.4 拷贝构造函数与赋值运算符

- **拷贝构造**：用一个对象初始化另一个对象时调用（`A a2 = a1;`）。
- **赋值运算符**：已存在的对象之间赋值时调用（`a2 = a1;`）。
- 拷贝构造调用时机：① 用一个对象初始化另一个对象；② 值传递参数；③ 值返回对象。
- **必须重写拷贝构造的情况**：类含动态内存分配（默认浅拷贝会导致多个对象指向同一块堆内存，析构时双重释放）；持有不可拷贝资源（文件句柄、网络连接）；需要严格控制拷贝语义（单例、引用计数）。

### 2.4.5 构造函数与析构函数

- 构造函数：初始化对象；可以有参/无参；可以被重载。
- 析构函数：销毁对象、释放资源；**不能重载**（销毁语义唯一，无需参数化）。
- **析构函数必须声明为虚函数**（当类将被继承时）：否则通过基类指针 delete 派生类对象时不会调用派生类析构函数，导致资源泄漏。
- 调用顺序：**构造先基类后派生**（虚基类由最底层派生类直接调用）；**析构先派生后基类**（与构造相反）。

### 2.4.6 初始化成员列表（哪些情况必须用）

- 初始化**引用类型成员**（引用必须在创建时绑定，不能重新赋值）。
- 初始化 **const 成员**（只能在初始化时赋值）。
- 初始化**无默认构造函数的类成员**（必须显式调用带参构造）。
- 调用**基类的非默认构造函数**。
- 注意：初始化列表的执行发生在对象构造阶段；成员初始化顺序由**类中声明顺序**决定，与初始化列表书写顺序无关。

### 2.4.7 友元

- 友元打破封装：允许外部类或函数访问当前类的 private/protected 成员。
- **单向性**：A 声明 B 为友元，B 可以访问 A 的私有成员，但 A 不能访问 B 的私有成员。
- 使用场景：运算符重载（如流运算符）、工具函数访问私有数据。

### 2.4.8 抽象类与纯虚函数

- 抽象类：包含**至少一个纯虚函数**的类，不能实例化，只能作为基类。
- 派生类必须实现所有纯虚函数，否则仍是抽象类。
- 抽象类的**析构函数应为虚函数**。

```cpp
class Shape {                       // 抽象类
public:
    virtual double area() const = 0; // 纯虚函数
    virtual void draw() const {}     // 普通虚函数（可选默认实现）
};
```

### 2.4.9 运算符重载

- 意义：增强抽象性、提升可读性、简化逻辑、支持泛型。
- **不允许重载的 5 个运算符**：`::`（作用域）、`.`（成员访问）、`.*`（成员指针访问）、`?:`（三目）、`sizeof`（均不可重载）。
- 三种方式：成员函数、全局函数（非成员）、友元函数。
- **流运算符（`<<`/`>>`）不能通过成员函数重载**：成员重载要求左操作数是当前类对象，调用形式会变成"对象 << 流对象"，与常规用法相反。解决：重载为非成员（友元）函数——左操作数为流对象引用，右操作数为自定义类对象。
- 流运算符重载返回引用：为了支持**链式调用**（`cout << a << b`）并避免不必要的复制。

### 2.4.10 继承的优缺点

- **优点**：代码复用；层次化建模表达 is-a 关系；虚函数实现运行时多态；接口抽象符合开闭原则。
- **缺点**：子类与父类紧耦合，父类修改影响所有子类；多重继承/深层继承链复杂（菱形继承）；破坏封装（子类依赖父类 protected 细节）；方法污染（被迫继承不需要的方法）；继承关系编译期固化，动态扩展不如组合灵活。

### 2.4.11 设计不能被继承的类

- C++11 起用 `final` 关键字：`class B final : public A {}`。
- 经典做法：私有构造函数 + 静态工厂方法（无法被继承实例化）。

## 2.5 多态

### 2.5.1 静态多态与动态多态

- **静态多态（编译时）**：函数重载、运算符重载、模板。
- **动态多态（运行时）**：虚函数 + 继承，运行时通过虚表确定调用目标。

### 2.5.2 虚函数实现原理（VTable / vptr）

1. **虚函数表（VTable）**：每个含虚函数的类对应一张表，是**函数指针数组**，每个条目对应一个虚函数；编译器编译期生成，存放于只读数据段。
2. **虚表指针（vptr）**：每个对象内存布局中有一个隐式指针指向所属类的 VTable。
3. 派生类重写虚函数 → VTable 对应条目指向派生类实现；未重写 → 仍指向基类实现。
4. 调用虚函数时通过对象 vptr → VTable → 函数指针，实现**动态绑定**。

### 2.5.3 重载、重写、隐藏的区别

| 概念 | 条件 | 绑定 |
| --- | --- | --- |
| 重载（Overload） | 同一作用域、函数名相同、参数列表不同（与返回值无关） | 静态绑定（编译期） |
| 重写（Override） | 派生类重定义基类**虚函数**，返回值与参数列表一致 | 动态绑定（运行时，通过虚表） |
| 隐藏（Hiding） | 基类函数非虚但派生类同名；或基类虚函数但参数不同 | 静态绑定，子类同名函数屏蔽父类版本 |

### 2.5.4 子类覆盖函数不加 virtual 是否还能多态？

- **能**。虚函数的特性会**隐式继承**到子类的覆盖函数中——子类重写基类虚函数即使不写 `virtual`，该函数仍是虚函数，通过虚表动态绑定实现多态（与是否显式加 virtual 无关）。

### 2.5.5 虚函数与普通成员函数的存储位置

- 虚函数表（VTable）与函数代码存放在**只读代码段/数据段**；vptr 存放在**对象内部**（通常对象内存布局首部）。
- 普通成员函数代码同样在代码段；对象中不存储普通函数。

## 2.6 C++11 与工程实践

### 2.6.1 auto、智能指针、四种 cast

- `auto`：类型推导；`auto` 作返回值（C++14 起）需与模板/decltype 配合使用。
- 四种 cast：
  - `static_cast`：编译期类型转换（一般类型转换）。
  - `dynamic_cast`：运行时安全检查（多态类型向下转换，失败返回 nullptr / 抛异常）。
  - `const_cast`：去除/添加 const。
  - `reinterpret_cast`：底层位模式重新解释（危险，慎用）。
- 智能指针：`unique_ptr` / `shared_ptr` / `weak_ptr`（见 §2.1.5）。

### 2.6.2 常用设计模式

- **单例**：全局唯一实例，全局访问点（注意线程安全、生命周期）。
- **工厂**：将对象创建逻辑与使用逻辑解耦（简单工厂、工厂方法、抽象工厂）。
- **代理**：为对象提供替身，控制访问（延迟加载、权限控制）。
- **适配器**：将不兼容的接口转换为客户端期望的接口。

### 2.6.3 提高 C++ 性能的手段（常见追问）

- 减少临时对象：返回值优化（RVO）、移动语义、`operator=` 复用。
- 内联技巧、条件内联；用函数对象/`std::function` 代替函数指针。
- 内存池、对象池；缓存友好（局部性）；预计算；延迟计算。
- 高效数据结构（vector 预留容量、map 换 unordered_map 等）。

## 2.7 其他高频考点

### 2.7.1 sizeof 与 strlen

- `sizeof`：编译期运算符，求**类型或变量占用字节数**（含字符串的 `\0`，数组不退化）。
- `strlen`：运行时函数，求字符串**字符个数**（不含 `\0`），遇到 `\0` 停止。

### 2.7.2 strcpy、sprintf 与 memcpy 的区别

- `strcpy`：字符串拷贝，遇 `\0` 停止；不检查目标缓冲区大小，易溢出。
- `sprintf`：格式化输出到字符串缓冲区（`snprintf` 更安全）。
- `memcpy`：按字节数拷贝内存（不关心内容），需指定长度，效率高。

### 2.7.3 位操作：某位清 0 / 置 1

```cpp
void clear_bit(unsigned int *x, int n) { *x &= ~(1U << n); }  // 第 n 位清 0
void set_bit(unsigned int *x, int n)   { *x |= (1U << n); }   // 第 n 位置 1
```

### 2.7.4 全局变量与局部变量的内存区别

- 全局变量/静态变量：静态存储区，程序启动时分配，生命周期为整个程序。
- 局部变量：栈上，函数调用时分配、返回时自动释放。
- 同名时局部变量遮蔽（Shadowing）全局变量，在其作用域内可见。

### 2.7.5 堆栈溢出一般由什么导致

- 递归过深（无终止条件或深度过大）。
- 局部变量过大（大数组/大对象分配在栈上）。
- 栈上动态分配过多（alloca 等）。

### 2.7.6 Debug 与 Release 版本的区别

- Debug：含调试信息，未优化，便于断点调试，运行慢、体积大。
- Release：编译器优化，无调试符号，运行快、体积小，行为可能与 Debug 不同（如未定义行为更明显）。

### 2.7.7 其他零散考点（速记）

- `#include <filename.h>` 搜索系统/标准库路径；`#include "filename.h"` 先搜索当前工程路径。
- `#error` 的作用：编译期输出错误信息并终止编译（如 `#if !defined(...) #error ...` 防止头文件重复包含的宏保护）。
- `switch` 参数必须是**整型或枚举类型**（不能是浮点、字符串）。
- `char`/`int`/`float`/`double` 在 Win32 下分别占 1/4/4/8 字节。
- 字符常量（`'A'`）sizeof 为 1；字符串常量（`"A"`）sizeof 为 2（含 `\0`）。
- 死循环写法：`for(;;)` 或 `while(1)`。
- 声明与定义：声明不分配空间、可多次；定义分配空间、只能一次。
- 变量声明 `short i = 0; i = i + 1L;`：i 是 short，+1L（long）结果先提升为 long，赋值回 short 可能**截断/警告**（依赖值是否超范围）。
- `&&`/`||` 有短路求值；`&`/`|` 是按位运算（无短路）。
- 静态库（.a/.lib）：链接时被复制进可执行文件；动态库（.so/.dll）：运行时加载共享（省内存、可热更新）。
- `main` 函数执行前：全局/静态对象构造、库初始化等。
- struct 与 union：union 所有成员共享同一块内存，同一时刻只能存其中一个成员。
- assert：调试期断言，条件为假时中止程序；Release 编译可关闭（NDEBUG）。
- 字符串转数字：`strtol(str, &endptr, 10)` 或 C++11 `std::stoi` / `std::stod`。
- 判断两个平面是否相交（不用碰撞体）：用平面方程比较法向量与点距，或求解两平面方程组看是否有解。

## 2.8 零散补充题（C++ 面试题 docx 收录）

- **成员函数靠什么区分不同对象的成员数据？** → **this 指针**：每个非静态成员函数调用时，编译器自动传入一个指向当前对象的指针（this）；不同对象的成员变量在内存中独立存储，通过 this 定位到各自的数据。
- **在类内部定义成员函数的函数体，该函数具备什么属性？** → 编译器会将其视为**内联函数**（隐式 inline）。
- **常对象（const 对象）**：被 `const` 修饰的类对象；其非 mutable 成员变量不可修改，只能调用**常成员函数**，必须通过构造函数在定义时初始化。
- **IP 地址的编码分为哪两部分？** → **网络部分**（网络号，标识所在网络）和**主机部分**（主机号，标识网络内主机），子网掩码用于划分两者。
- **何时需要预编译？** → ① 头文件包含大量稳定代码时用**预编译头（PCH）**减少重复编译时间；② 用条件编译宏（`#ifndef` 等）防止头文件重复包含；③ 平台差异代码用 `#ifdef _WIN32` 等条件编译。
- **对象之间怎样实现数据共享？** → 通过**静态成员变量**（属于类、所有实例共享一份），或通过指针/引用传递同一个对象。
- **构造函数和析构函数何时被调用？是否需要手工调用？** → 栈对象：作用域进入/退出时自动调用；堆对象：`new`/`delete` 时自动调用。**一般不需要手工调用**；仅在 `placement new`（显式构造）、显式析构（`obj.~T()`，配合定位 new 使用）等特殊场景才手工调用。
- **define 与 const 的区别**：`#define` 是**预处理期文本宏替换**，无类型检查、无作用域、不占内存（编译后不存在）；`const` 是**编译期常量**，有类型检查、遵守作用域规则、占用存储（或编译期折叠）。
- **简述枚举类型（enum）**：定义一组具名的整型常量（枚举成员），默认从 0 开始递增，可显式指定值；C++11 强类型枚举 `enum class` 更安全（需显式作用域、不隐式转 int）。
- **全局变量的优缺点**：优点——全局可见、方便共享、生命周期贯穿程序；缺点——破坏封装、易命名冲突、难以追踪修改、多线程不安全、增加耦合。
- **类的声明与实现分开的好处**：降低编译依赖（改动实现无需重新编译所有使用者）、接口与实现解耦、便于团队协作与库发布（二进制兼容）、隐藏实现细节。
- **QT 信号槽机制（简述）**：信号（signal）与槽（slot）通过 `connect` 连接；对象状态变化时发射信号，框架调用已连接的槽函数——本质是**类型安全的回调/观察者机制**，解耦发送方与接收方（线程安全的队列连接方式可跨线程）。
- **boost 常用类**：`thread`（线程）、`asio`（网络/异步 IO）、`signal`（信号槽）、`bind`/`function`（函数对象封装，C++11 已并入标准库）、`smart_ptr`（智能指针，已并入标准库）。
