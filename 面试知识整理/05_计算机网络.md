# 五、计算机网络

## 5.1 网络基础

### 5.1.1 网络分类

- **局域网（LAN）**：某一小区域内多台设备互联的计算机组。
- **城域网（MAN）**：一个城市范围内，几十到一百公里。
- **广域网（WAN）**：连接不同地区/城市/国家的远程网络，几十到几千公里。
- **互联网（因特网）**：目前国际上最大的网络，定义了通信规则等。
- **万维网（WWW）**：基于互联网的网站和网页的统称。
- **以太网**：网络连接的一种规则，定义了连接传输规范。

### 5.1.2 常见网络拓扑

总线型、星型、环形、树型、网状、混合型。

### 5.1.3 设备如何通信 / IP 与端口

- 原理：设备通过物理连接互联，数据封装成带地址信息的数据包，经路由选择合适的路径，经过多个中间节点到达目的地；接收端解封装交给应用程序；过程含错误检测与纠正。
- **IP 地址**：唯一标识网络中的每个设备。
- **端口**：区分同一设备上的不同服务/应用程序。
- 两者结合确保数据能从源设备的一个应用准确发送到目标设备的对应应用。

### 5.1.4 OSI 七层模型

| 层 | 功能 |
| --- | --- |
| 物理层 | 物理接口标准（电压、线缆、插头），提供比特流传输 |
| 数据链路层 | 相邻节点间数据帧可靠传输，含错误检测/纠正、流量控制（LLC、MAC 子层） |
| 网络层 | 源到目的的数据包路由选择、逻辑寻址（IP、ICMP） |
| 传输层 | 端到端可靠传输（TCP、UDP），含流量控制、拥塞控制 |
| 会话层 | 会话的建立、管理和终止，同步与恢复会话 |
| 表示层 | 数据格式化、加密解密、压缩 |
| 应用层 | 应用程序间通信服务（HTTP、FTP、SMTP、DNS 等） |

### 5.1.5 TCP/IP 四层模型

| 层 | 主要协议/功能 |
| --- | --- |
| 应用层 | HTTP、FTP、SMTP、DNS 等 |
| 传输层 | TCP、UDP |
| 网络层 | IP（寻址与路由）、ICMP |
| 链路层 | ARP、RARP、以太网协议等 |

### 5.1.6 游戏服务器架构

- 布局架构：**分布式**（多服务器实例 + 负载均衡）。
- 通信模型：**C/S 客户端/服务器模型**。
- 服务器通常处理：状态同步（位置、物品、血量）、逻辑处理（剧情/NPC）、网络通信、安全验证、负载均衡、数据存储、虚拟货币交易。

## 5.2 TCP 与 UDP

### 5.2.1 TCP 特点

- 面向连接（传输前需建立连接）。
- 可靠传输：超时未收到 ACK 则重传；序列号保证按顺序重组。
- 流量控制：滑动窗口协议动态调整发送速率，避免接收方缓冲区溢出。
- 拥塞控制：慢启动、拥塞避免、快速重传、快速恢复。
- 全双工通信；头部 20 字节；开销大（三次握手/四次挥手）。
- 应用：文件传输（FTP）、网页浏览（HTTP/HTTPS）、邮件（SMTP/IMAP/POP3）。

### 5.2.2 UDP 特点

- 无连接，不可靠（无 ACK、无重传），无顺序控制。
- 轻量高效：头部仅 8 字节，延迟低。
- 支持广播和多播（一对多/多对多）。
- 应用：视频会议、在线游戏、语音通话（VoIP）、流媒体等实时性要求高的场景。

### 5.2.3 TCP 三次握手与四次挥手

**三次握手（建立连接）**

1. 第一次：客户端发送 **SYN**（请求建立连接）；
2. 第二次：服务端回复 **SYN + ACK**（确认收到）；
3. 第三次：客户端发送 **ACK**（确认建立）。

**四次挥手（断开连接）**

1. 客户端发送 **FIN**（请求断开）；
2. 服务端回复 **ACK**（收到断开请求）；
3. 服务端发送 **FIN**（服务端准备断开）；
4. 客户端发送 **ACK**（确认断开）。

### 5.2.4 TCP 如何确保可靠传输

1. **序列号与确认机制**：序列号标识报文段第一个字节序号；接收方发送 ACK 确认，未收到则重传。
2. **重传机制**：超时重传；快速重传——接收方收到乱序报文段会发送重复 ACK，发送方收到 3 个重复 ACK 后立即重传丢失段。
3. **流量控制**：滑动窗口——接收方通过窗口大小字段告知可接收的数据量，发送方据此调整速率，避免缓冲区溢出。
4. **拥塞控制**：
   - 慢启动：从 1 个 MSS 开始，每收到一个 ACK 窗口 +1 MSS（每个 RTT 约翻倍），直到达到慢启动阈值；
   - 拥塞避免：达到阈值后窗口线性增长；
   - 快速恢复：发生拥塞后窗口减半，进入快速恢复，避免窗口骤降。

## 5.3 HTTP 与 DNS

- **HTTP 连接建立流程**：DNS 解析 → TCP 三次握手 → HTTP 请求与响应。
- **DNS 解析作用**：域名到 IP 的映射、负载均衡、故障转移、CDN 加速。
- **协议层次**：DNS 应用层、TCP 传输层、HTTP 应用层。
- **网络协议的作用（一句话）**：定义数据在网络中传输的规则和标准，确保不同系统之间能正确交换信息。

## 5.4 Socket 与游戏网络

### 5.4.1 什么是 Socket

- Socket 是网络编程的抽象接口，封装了 TCP/UDP 通信细节；客户端通过 Socket 建立连接、发送/接收数据；服务端通过监听 Socket 接受连接。

### 5.4.2 长连接与短连接

- **短连接**：每次通信都建立/断开连接（三次握手 + 四次挥手），适合低频请求（如 HTTP）。
- **长连接**：连接建立后保持复用，适合高频交互（游戏、即时通信）；需要心跳保活、断线检测。

### 5.4.3 心跳包与断线重连

- **心跳包**：客户端/服务器定时发送的小数据包，用于确认对方在线、检测断线、保持 NAT/防火墙映射（防止连接被回收）。
- **断线重连**：
  - 检测断线：超时检测、心跳包等；
  - 重连策略：指数退避、随机退避等；
  - 状态恢复：重连成功后恢复之前的连接状态；
  - 错误处理：处理重连过程中的各种异常。

### 5.4.4 5000 个客户端连接的处理方案

- 不能为每个连接开一个线程（线程开销太大）。
- 方案：**单线程 + 事件循环 / IO 多路复用**（select/poll/epoll/IOCP），配合**线程池**处理业务逻辑；游戏服务器常用 **Actor/异步消息模型**，客户端连接由事件驱动而非线程驱动。

### 5.4.5 客户端与服务器交互方式

- 请求-响应（同步/异步回调）、推送（服务器主动下发）、长连接实时同步、RPC（远程过程调用）。

### 5.4.6 浮点数最小传输量问题

- 题目：属性 a 为浮点数，最大 10000，保留 4 位小数（如 4.0643），如何用最少数据量传输？
- 思路：**定点化**——把小数放大 10⁴ 倍转成整数传输：`4.0643 * 10000 = 40643`，用 **4 字节 int32** 传输；接收端除以 10000 还原。比直接传字符串/浮点字符串更省带宽。

### 5.4.7 Unity 连接数据库

- 客户端一般不直接连数据库（安全性差）；常见做法：客户端通过 HTTP/WebSocket 请求服务器，由服务器访问数据库（MySQL/SQL Server 等），或使用 UnityWebRequest 调用后端 API；编辑器内可用 ODBC/第三方插件直连调试。

## 5.5 游戏同步：状态同步 vs 帧同步

| 对比项 | 状态同步 | 帧同步 |
| --- | --- | --- |
| 同步内容 | 服务器定期下发游戏**完整状态**（位置、血量等） | 服务器只同步玩家**输入指令** |
| 计算位置 | 服务器计算所有游戏逻辑 | 各客户端按相同初始状态 + 输入**独立计算** |
| 带宽 | 大（状态复杂时消耗大） | 小（只传输入） |
| 响应速度 | 延迟较高 | 快、流畅 |
| 安全性 | 高，逻辑在服务器，难作弊 | 低，客户端可作弊 |
| 实现复杂度 | 简单，逻辑集中 | 复杂，需保证各端逻辑一致（确定性） |
| 适用场景 | MMORPG、回合制等实时性要求不高的游戏 | MOBA、RTS 等实时性要求高的游戏 |

## 5.6 加密与安全

- 按加解密密钥是否相同分为两大类：
- **对称加密**：同一密钥加密解密。常见：AES（高级加密标准，广泛使用）、DES（早期标准，已不推荐）、3DES（DES 的改进）。
- **非对称加密**：一对密钥（公钥 + 私钥）。公钥加密、私钥解密。常见：RSA（加密 + 数字签名）、DSA（主要用于数字签名）。
- **公钥与私钥**：公钥公开用于加密/验签；私钥保密用于解密/签名；公钥加密的数据只有对应私钥能解。
